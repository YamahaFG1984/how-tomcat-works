第 13 章

Host 与 Engine

一个 Tomcat 里要跑多个 Web 应用，就需要 Host（虚拟主机）把请求按上下文路径分给不同的 Context； 一台服务器要服务多个域名，就需要 Engine（引擎）按 Host 请求头把请求分给不同的 Host。 至此，四种容器全部登场。

本章目标

  • 理解 Host 如何用「最长上下文路径前缀」选择 Context
  • 理解 Engine 如何按主机名选择 Host，以及默认主机的作用
  • 知道为什么实际部署中「离不开 Host」
  • 亲手搭一个支持虚拟主机的服务器

全景：一个请求如何找到它的 Servlet

Host 接口与 StandardHost

如果只有一个 Context，理论上可以不要 Host——Context 接口的文档说它的父容器「通常是 Host，但也可以是别的实现，甚至省略」。但实际部署中总是需要 Host，原因见下文。

public interface Host extends Container {
    public String getAppBase();                 // 应用根目录，例如 webapps
    public void setAppBase(String appBase);
    public boolean getAutoDeploy();             // 是否自动发现并部署 appBase 下的应用（第 18 章）
    public void setAutoDeploy(boolean autoDeploy);
    public String getName();                    // 虚拟主机的完整域名
    public void addAlias(String alias);         // 别名，也映射到这个 Host
    public String[] findAliases();
    public Context map(String uri);             // ★ 找处理这个 URI 的 Context
    ...
}

StandardHost 继承 ContainerBase，构造器设置基础阀 StandardHostValve；start() 时额外往管道里加两个阀：ErrorReportValve（生成错误页面）和 ErrorDispatcherValve（转发到 web.xml 里配置的错误页）。

map()：最长上下文路径前缀

public Context map(String uri) {
    if (uri == null)
        return (null);
    Context context = null;
    String mapuri = uri;
    while (true) {
        context = (Context) findChild(mapuri);      // 子容器的名字就是上下文路径
        if (context != null)
            break;
        int slash = mapuri.lastIndexOf('/');
        if (slash < 0)
            break;
        mapuri = mapuri.substring(0, slash);        // 去掉最后一段再试
    }
    if (context == null)
        context = (Context) findChild("");          // 默认 Context（ROOT）
    return (context);
}

Tomcat 4 中还有一个 StandardHostMapper（由 ContainerBase 的 addDefaultMapper 创建），它的 map(request, update) 只是调用 host.map(uri)，并在 update 为 true 时把 Context 和上下文路径写回请求。Tomcat 5 去掉了 Mapper，Context 直接从请求对象中取得。

为什么离不开 Host

只要 Context 由 ContextConfig 配置（正式部署都是这样），就必须有 Host。ContextConfig 要读 /WEB-INF/web.xml，它调用 servletContext.getResource()，而 ApplicationContext.getResource() 里有这样一行：

DirContext resources = context.getResources();
if (resources != null) {
    String fullPath = context.getName() + path;
    // this is the problem. Host must not be null
    String hostName = context.getParent().getName();

没有父容器，getParent() 返回 null，直接 NullPointerException。所以除非你自己写 ContextConfig，否则必须有 Host。

Engine 接口与 StandardEngine

Engine 代表整个 Catalina Servlet 引擎，如果有，它一定是顶层容器。要支持多个虚拟主机就需要它；默认的 Tomcat 部署也总是用 Engine，里面至少有一个默认主机。

public interface Engine extends Container {
    public String getDefaultHost();              // 找不到匹配的 Host 时使用
    public void setDefaultHost(String defaultHost);
    public String getJvmRoute();                 // 集群中区分节点（会话 ID 后缀）
    public void setJvmRoute(String jvmRouteId);
    public Service getService();                 // 所属的 Service（第 14 章）
    public void setService(Service service);
    ...
}

public StandardEngine() {
    super();
    pipeline.setBasic(new StandardEngineValve());
}

public void addChild(Container child) {
    if (!(child instanceof Host))                          // 子容器只能是 Host
        throw new IllegalArgumentException(sm.getString("standardEngine.notHost"));
    super.addChild(child);
}

public void setParent(Container container) {                // 顶层容器没有父容器
    throw new IllegalArgumentException(sm.getString("standardEngine.notParent"));
}

StandardEngineValve

ⓘ Host 请求头是虚拟主机的基础

HTTP/1.1 强制要求请求带 Host 头，正是为了让一个 IP 地址上可以托管多个网站。HTTPS 时代还多了一个难题：TLS 握手发生在 HTTP 请求之前，服务器在握手时就得知道用哪个域名的证书——这由 TLS 扩展 SNI 解决，Tomcat 8.5 起支持在一个连接器上为多个主机名配置不同证书。

本章应用

两个应用都部署 webapps/app1（上下文路径 /app1，包含 Primitive 和 Modern）：

应用 1：Host 是顶层容器
Context context = new StandardContext();
context.setPath("/app1");
context.setDocBase("app1");
context.addChild(wrapper1);
context.addChild(wrapper2);
...
Host host = new StandardHost();
host.addChild(context);
host.setName("localhost");
host.setAppBase("webapps");
connector.setContainer(host);
((Lifecycle) host).start();
应用 2：Engine 是顶层容器
Host host = new StandardHost();
host.addChild(context);
host.setName("localhost");
host.setAppBase("webapps");
...
Engine engine = new StandardEngine();
engine.addChild(host);
engine.setDefaultHost("localhost");
connector.setContainer(engine);
((Lifecycle) engine).start();

两个应用都通过 http://localhost:8080/app1/Primitive 和 /app1/Modern 访问。

Java 17 对照版

源码java17/src/main/java/modern/ch13/core/startup/Bootstrap1.javastartup/Bootstrap2.javatomcat/EmbeddedVirtualHosts.javajava17/webapps/app1/

Java 17 版在迷你容器中实现了 StandardHost、StandardEngine 及其基础阀。为了让虚拟主机真正可用，第 3 章的 HttpRequest 增加了两处：getServerName() 改为解析 Host 请求头，getContextPath() 由 Host 在映射时设置。Bootstrap2 比原书多了一个虚拟主机 www.example.com（别名 example.com）。

① Engine 的主机选择：名字 → 别名 → 默认主机

public StandardHost map(String serverName) {
    if (serverName != null) {
        String name = serverName.toLowerCase();            // 主机名大小写不敏感
        Container host = findChild(name);
        if (host != null) return (StandardHost) host;
        for (Container child : findChildren()) {
            if (((StandardHost) child).findAliases().contains(name)) {
                return (StandardHost) child;
            }
        }
    }
    return defaultHost == null ? null : (StandardHost) findChild(defaultHost);
}

② Host 阀：记得恢复上下文类加载器

StandardContext context = host.map(request.getRequestURI());
if (context == null) {
    response.sendError(HttpServletResponse.SC_NOT_FOUND, "No context for " + request.getRequestURI());
    return;
}
request.setContextPath(context.getPath());

Thread thread = Thread.currentThread();
ClassLoader original = thread.getContextClassLoader();
thread.setContextClassLoader(context.getLoader().getClassLoader());
try {
    context.invoke(request, response);
} finally {
    thread.setContextClassLoader(original);     // 原书没有恢复：线程池里的线程下次可能带着别的应用的类加载器
}
⚠ 线程上下文类加载器要「谁设置谁恢复」

连接器的处理器线程是复用的。如果 Host 阀设置了 A 应用的类加载器却不恢复，下一个请求在进入 B 应用之前就带着 A 的类加载器，可能导致类加载错乱、甚至让 A 应用的类加载器在重载后无法被回收（内存泄漏）。Tomcat 后来的版本都用 try/finally 恢复。

③ Host 启动时加一个错误报告阀

对应 Tomcat 的 ErrorReportValve：后面的组件抛异常时，返回一个 500 页面，而不是让异常冒泡到连接器。

④ Tomcat 11：两个虚拟主机

// 默认主机 localhost：tomcat.getHost() 自动创建并设为 Engine 的 defaultHost
Context app1 = tomcat.addContext(tomcat.getHost(), "/app1", Path.of("webapps/app1").toAbsolutePath().toString());
Tomcat.addServlet(app1, "Primitive", "PrimitiveServlet");
app1.addServletMappingDecoded("/Primitive", "Primitive");

// 第二个虚拟主机
var example = new StandardHost();
example.setName("www.example.com");
example.addAlias("example.com");
tomcat.getEngine().addChild(example);
Context root = tomcat.addContext(example, "", Path.of("myApp").toAbsolutePath().toString());   // ROOT 应用
Tomcat.addServlet(root, "Hello", "HelloServlet");
root.addServletMappingDecoded("/Hello", "Hello");

💡 本地测试虚拟主机的两种方法

一是像上面那样用 curl -H 'Host: ...' 手动指定请求头；二是在 /etc/hosts（Windows 是 C:\Windows\System32\drivers\etc\hosts）里加一行 127.0.0.1 www.example.com，然后浏览器访问 http://www.example.com:8080/Hello。

设计要点

这一章的代码里有几个可以带到别的项目里的设计决定。每条按「做法 → 取舍 → 替代方案 → 还能用在哪」来写；系统的讨论见设计篇。

1每一层只做一次路由

Engine 按 Host 头选 Host，Host 按路径选 Context，Context 按 Servlet 路径选 Wrapper。

取舍
每层的规则都很简单；代价是请求要经过多层调用（Tomcat 后来把映射合并到连接器的 Mapper 里，一次查完）。
还能用在
多租户系统：先按域名选租户，再按路径选模块，最后选具体处理器。
延伸：第 29 章 · 整体架构：分层与边界
2总有一个默认值

Host 头不匹配任何虚拟主机时，交给 defaultHost。

取舍
不会因为一个陌生的 Host 头就返回错误；但要注意默认主机不应暴露敏感应用。
还能用在
路由、配置、策略选择都应该有显式的兜底项。
延伸：第 29 章 · 整体架构：分层与边界
3错误页渲染也是一个阀

ErrorReportValve 在请求处理完之后检查状态码，统一生成错误页面。

取舍
业务代码只需 sendError(404)，页面样式集中在一处。
还能用在
统一异常处理（Spring 的 @ControllerAdvice）。
延伸：第 30 章 · 扩展点设计
4状态反映到协议上

Context 停止时返回 503 Service Unavailable，而不是 500 或 404。

取舍
客户端和负载均衡器能区分「暂时不可用」和「出错了」，从而重试或切换节点。
还能用在
健康检查、维护模式、降级：用正确的状态码表达服务状态。
延伸：第 32 章 · 并发、隔离与演进

小结

  • Host 用最长上下文路径前缀选择 Context，找不到就用路径为 "" 的 ROOT 应用。
  • StandardHostValve 选定 Context、绑定其类加载器、更新会话访问时间，再调用 Context。
  • ContextConfig 依赖 Host（context.getParent().getName()），所以实际部署离不开 Host。
  • Engine 是顶层容器，子容器只能是 Host；StandardEngineValve 检查 Host 头并选择 Host，找不到就用默认主机。
  • 至此四种容器的分派链完整：Engine（主机名）→ Host（上下文路径）→ Context（Servlet 映射）→ Wrapper。
