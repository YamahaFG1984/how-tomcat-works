第 22 章 · 补充篇

静态资源、错误页与字符编码

第 1 章的服务器只会把文件原样读出来。真实的 Tomcat 在「读文件」这件小事上做了很多： 欢迎文件、目录重定向、ETag 与 304、断点续传用的 Range。 出错时它还要把请求转到应用自己的错误页。最后是让无数新手头疼的中文乱码： 一个请求里有三处地方各自决定用什么编码。这一章把这三件事讲清楚，并写一个迷你 DefaultServlet 和 Tomcat 的版本对照。

本章目标

  • 知道 DefaultServlet 何时被调用，以及目录、欢迎文件的处理流程
  • 理解条件请求（ETag、Last-Modified）如何让浏览器缓存生效
  • 会用 Range 请求，理解 206 和 416
  • 说出异常和 sendError 是怎样被转到 error-page 的，没配置时谁来兜底
  • 分清 URI、请求体、响应体三处编码各由什么决定，能定位乱码的原因

DefaultServlet：没人认领的请求

第 12 章讲过映射规则的最后一条：前面都不匹配时，交给映射到 / 的默认 Servlet。 Tomcat 在全局的 conf/web.xml 里把 org.apache.catalina.servlets.DefaultServlet 注册为默认 Servlet， 所以每个应用不用写任何配置就能提供 HTML、CSS、图片。它的处理流程是这样的：

为什么目录一定要补上结尾的 /？因为浏览器按 URL 解析相对链接：在 /docs 页面里写 <link href="style.css"> 会请求 /style.css，而在 /docs/ 里才会请求 /docs/style.css。欢迎文件列表来自 web.xml 的 <welcome-file-list>， 目录列表默认关闭（listings=false），生产环境也应该保持关闭。

💡 欢迎文件其实分两步

Tomcat 的欢迎文件处理大部分发生在 Mapper 里，而不是 DefaultServlet：请求 /docs/ 时， Mapper 依次尝试 /docs/index.html 等欢迎文件，如果对应的资源存在就直接映射过去。 所以欢迎文件也可以是一个 Servlet 路径，不一定是静态文件。

条件请求：ETag 与 304

浏览器缓存了一个文件之后，下次还要不要下载？它会带上上次收到的「版本标识」去问服务器， 文件没变就只回一个 304 Not Modified，没有响应体。版本标识有两种：

服务器给出浏览器下次带上比较方式特点
ETag: W/"长度-修改时间"If-None-Match字符串相等（弱比较忽略 W/）精确；Tomcat 默认用文件长度和修改时间拼出来，所以是「弱」ETag
Last-ModifiedIf-Modified-Since修改时间 ≤ 浏览器给的时间只精确到秒，一秒内改两次会漏判

两者同时出现时，If-None-Match 优先（RFC 9110 的规定）。如果想让浏览器连这一次往返也省掉， 要再配合 Cache-Control: max-age=…，那属于缓存策略，通常由过滤器或前端的 CDN 来设置。

范围请求：Range 与 206

下载工具的断点续传、视频播放器的拖动进度条，靠的都是 Range 请求头：只要文件的一部分。 服务器用 Accept-Ranges: bytes 声明自己支持，然后用 206 Partial Content 和 Content-Range 回答；范围超出文件大小就返回 416。

还有一个容易忽略的细节：If-Range。客户端续传时会带上之前的 ETag，如果文件已经变了， 服务器必须忽略 Range、返回整个新文件——否则把新文件的后半段拼到旧文件的前半段上，下载结果就坏了。

错误处理：从异常到错误页

Servlet 抛出异常、或者调用 response.sendError(404) 之后，并不是直接把错误返回给浏览器。 请求会一路回到 Host 层，由 StandardHostValve 根据 web.xml 的 <error-page> 决定下一步： 

<error-page>
  <error-code>404</error-code>
  <location>/errors/404</location>
</error-page>
<error-page>
  <exception-type>java.lang.IllegalStateException</exception-type>
  <location>/errors/exception</location>
</error-page>
<!-- Servlet 3.0 起可以不写 code 和 type，作为「默认错误页」 -->

这和第 21 章的 forward 是同一套分派机制，只是 DispatcherType 换成了 ERROR。 第 13 章见过的 ErrorReportValve 是最后一道防线，它默认会输出异常消息和 Tomcat 版本号—— 对攻击者来说是很有用的信息，第 28 章会把它关掉。

乱码几乎都是「编码的人和解码的人用了不同的字符集」。一个 HTTP 交互里有三处需要把字节和字符互相转换， 它们各自独立决定用什么字符集：

这正是下面运行结果里看到的现象：同一个「中文」，放在查询串里能正确解码，放在 POST 表单里就变成了 ä¸­æ——UTF-8 的 6 个字节被当作 6 个 ISO-8859-1 字符。修复方法从好到差：

  1. 在 web.xml 里声明 <request-character-encoding>UTF-8</request-character-encoding> 和 <response-character-encoding>（Servlet 4.0 起），一次解决整个应用。
  2. 用一个最先执行的过滤器调用 request.setCharacterEncoding("UTF-8")（老项目常见的 SetCharacterEncodingFilter / Spring 的 CharacterEncodingFilter）。必须在第一次读参数之前调用，否则无效。
  3. 在每个 Servlet 里手动设置——容易漏，不推荐。
✅ 静态文件的编码

DefaultServlet 返回 text/html 时默认不带 charset，浏览器会去读页面里的 <meta charset="utf-8">。也可以在 mime-mapping 里直接写 text/html;charset=UTF-8（本章验证过，Tomcat 11 会原样使用）。

② ETag、Last-Modified 与 304

long length = Files.size(file);
long lastModified = Files.getLastModifiedTime(file).toMillis() / 1000 * 1000;   // HTTP 日期只精确到秒
String etag = "W/\"" + length + "-" + lastModified + "\"";        // 和 Tomcat 默认格式一样
resp.setHeader("ETag", etag);
resp.setDateHeader("Last-Modified", lastModified);
resp.setHeader("Accept-Ranges", "bytes");

if (notModified(req, etag, lastModified)) {
    resp.setStatus(HttpServletResponse.SC_NOT_MODIFIED);
    return;                                                       // 不写响应体
}

/** If-None-Match 优先；没有它时才看 If-Modified-Since */
static boolean notModified(HttpServletRequest req, String etag, long lastModified) {
    String inm = req.getHeader("If-None-Match");
    if (inm != null) {
        for (String tag : inm.split(",")) {
            String t = tag.trim();
            if (t.equals("*") || weakEquals(t, etag)) return true;
        }
        return false;
    }
    long ims = req.getDateHeader("If-Modified-Since");
    return ims != -1 && lastModified <= ims;
}

③ Range：只拷贝需要的字节

设计要点

这一章的代码里有几个可以带到别的项目里的设计决定。每条按「做法 → 取舍 → 替代方案 → 还能用在哪」来写；系统的讨论见设计篇。

1兜底处理器

映射规则的最后一条永远是默认 Servlet，任何请求都有人处理，哪怕只是回一个 404。

取舍
不会出现「请求掉进黑洞」；但应用把 / 映射给自己的 Servlet 时，静态文件就没人管了（Spring MVC 早期的经典问题）。
还能用在
消息路由的死信队列、命令分派的 unknown 命令处理、规则引擎的默认规则。
延伸：第 29 章 · 整体架构：分层与边界
2用版本号做缓存校验

ETag 用「长度 + 修改时间」快速算出一个版本号，客户端拿版本号来问「变了没有」。

取舍
不用读文件内容就能算出来，非常便宜；代价是弱校验——内容变了但长度和时间碰巧不变时会误判。
替代方案
内容哈希做强 ETag（准确，但要读完整个文件）。
还能用在
REST API 的乐观锁（If-Match）、增量同步、客户端配置拉取：用版本号避免重复传输。
延伸：第 32 章 · 并发、隔离与演进
3错误处理集中在上层

Servlet 只负责抛异常或 sendError，由 Host 阀统一查表、分派到错误页，最后由 ErrorReportValve 兜底。

取舍
错误页风格一致、业务代码干净；代价是错误流程跨越多层，响应一旦提交就无法再改。
还能用在
Spring 的 @ControllerAdvice、gRPC 的拦截器统一映射状态码、CLI 工具在 main 里统一捕获并输出友好提示。
延伸：第 30 章 · 扩展点设计
4显式声明编码，不依赖默认值

规范的默认编码是 ISO-8859-1，Tomcat 为兼容性保留了它，正确做法是在应用层显式声明 UTF-8。

取舍
保留默认值不会破坏老应用；代价是每个新应用都要记得配置。
还能用在
任何字节和字符转换的地方：new String(bytes, UTF_8)、Files.readString(path, UTF_8)。JDK 18 起默认字符集已改为 UTF-8（JEP 400），但显式写出来永远不会错。

小结

  • DefaultServlet 映射到 /，处理所有没被认领的请求：目录补斜杠重定向、欢迎文件、关闭目录列表。
  • 条件请求用 ETag / Last-Modified 判断文件是否变化，没变就回 304 省掉响应体；If-None-Match 优先。
  • Range 请求返回 206 和 Content-Range，超出范围返回 416；If-Range 防止拼接出坏文件。
  • 异常和 sendError 由 StandardHostValve 查 error-page，找到就用 ERROR 分派转过去，找不到由 ErrorReportValve 输出默认页。
  • URI、请求体、响应体三处编码各自独立：URI 默认 UTF-8，后两者默认 ISO-8859-1，应在应用级声明 UTF-8。

动手练习

  1. 给 MiniDefaultServlet 加上预压缩支持：请求头包含 Accept-Encoding: gzip 且存在 xxx.gz 时，直接发送压缩文件并加 Content-Encoding: gzip 和 Vary: Accept-Encoding。
  2. 把 ETag 改成文件内容的 SHA-256（强 ETag），比较大文件时两种方式的开销。
  3. 给 Tomcat 版增加一个没有 code 和 type 的「默认错误页」，然后访问 /crash，看看它是否取代了 ErrorReportValve 的页面。
  4. 写一个只拦截 REQUEST 的过滤器调用 setCharacterEncoding("UTF-8")，挂到根应用上，确认 POST /echo 不再乱码；再把它挪到读参数之后调用，观察失效。
