第 19 章

Manager Servlet

Tomcat 自带一个 Manager 应用，可以通过浏览器或 HTTP 请求列出、启动、停止、重载、卸载其他 Web 应用。 可是普通的 Servlet 只能看到 Servlet API，凭什么它能操作容器内部？秘密在于一个特殊的接口： ContainerServlet。这一章看 Tomcat 如何「开一扇后门」给受信任的 Servlet，又如何守住这扇门。

本章目标

  • 了解 Manager 应用的部署方式、安全约束和可用命令
  • 理解 ContainerServlet 接口，以及 StandardWrapper 何时调用 setWrapper
  • 看懂 ManagerServlet 如何顺着 Wrapper → Context → Host 完成 list、start、stop
  • 理解 privileged 属性的意义

Manager 应用

Manager 应用的文件不在默认的 webapps 目录，而在 %CATALINA_HOME%/server/webapps/manager，靠描述符 manager.xml 部署。它有两个 Servlet：处理纯文本命令的 ManagerServlet（本章重点）和提供网页界面的 HTMLManagerServlet。整个应用受 BASIC 认证保护，只有 manager 角色的用户才能访问，所以要先在 tomcat-users.xml 里加一个用户：

<tomcat-users>
  <role rolename="manager"/>
  <user username="tomcat" password="tomcat" roles="manager"/>
</tomcat-users>

ContainerServlet 接口

public interface ContainerServlet {
    public Wrapper getWrapper();
    public void setWrapper(Wrapper wrapper);
}

实现了它的 Servlet，在加载时会收到代表自己的 StandardWrapper。有了 Wrapper，就能拿到它所在的 Context、Context 所在的 Host（也就是 Deployer），进而操作所有应用。

// loadServlet() 里
if ((servlet instanceof ContainerServlet) && isContainerProvidedServlet(actualClass)) {
    ((ContainerServlet) servlet).setWrapper(this);
}
servlet.init(facade);

// 对应原书 Listing 19.2
private boolean isContainerProvidedServlet(String classname) {
    if (classname.startsWith("org.apache.catalina.")) {
        return (true);
    }
    try {
        Class clazz = this.getClass().getClassLoader().loadClass(classname);
        return (ContainerServlet.class.isAssignableFrom(clazz));
    } catch (Throwable t) {
        return (false);
    }
}

public void setWrapper(Wrapper wrapper) {
    this.wrapper = wrapper;
    if (wrapper == null) {
        context = null;
        deployer = null;
    } else {
        context = (Context) wrapper.getParent();
        deployer = (Deployer) context.getParent();
    }
}

⚠ 这是一扇后门

能拿到 Wrapper 的 Servlet 几乎可以对容器做任何事。如果随便一个应用都能声明自己是 ContainerServlet，后果不堪设想。所以：① Tomcat 4 只给 org.apache.catalina. 包下、或容器类加载器能加载的 Servlet 调用 setWrapper；② Tomcat 5 起还要求所在 Context 设置了 privileged="true"，只有特权应用才能使用容器内部的类。

① 加载容器提供的 Servlet

private Servlet loadServlet() throws ServletException {
    String className = getServletClass();
    boolean privileged = getParent() instanceof StandardContext ctx && ctx.isPrivileged();
    ClassLoader loader = isContainerProvidedServlet(className) && privileged
            ? getClass().getClassLoader()                  // 容器的类加载器
            : getLoader().getClassLoader();                // Web 应用的类加载器
    var servlet = (Servlet) loader.loadClass(className).getDeclaredConstructor().newInstance();
    if (servlet instanceof ContainerServlet cs) {
        if (!privileged) {
            throw new SecurityException("Servlet " + className + " 需要 privileged=\"true\" 的 Context");
        }
        cs.setWrapper(this);
    }
    servlet.init(new SimpleServletConfig(name));
    return servlet;
}
🔑 为什么必须换类加载器？

第 8 章我们让 Web 应用的类加载器看不到容器类。ManagerServlet 却要用 StandardContext、StandardHost 这些容器类——如果由 Web 应用的类加载器加载它，连 ContainerServlet 接口都找不到。所以容器提供的 Servlet 必须用容器自己的类加载器加载：隔离和特权，是同一个机制的两面。

② switch 表达式分派命令

String command = request.getPathInfo() == null ? "/list" : request.getPathInfo();   // 映射 /* → pathInfo
String path = request.getParameter("path");
switch (command) {
    case "/list" -> list(writer);
    case "/start" -> manage(writer, path, "started", StandardContext::start);
    case "/stop" -> manage(writer, path, "stopped", StandardContext::stop);
    case "/reload" -> manage(writer, path, "reloaded", StandardContext::reload);
    case "/sessions" -> sessions(writer, path);
    case "/undeploy" -> undeploy(writer, path);
    default -> writer.println("FAIL - Unknown command " + command);
}

start / stop / reload 的检查逻辑完全相同（路径合法、应用存在、不是自己），所以抽成一个 manage(writer, path, done, action)，用方法引用 StandardContext::start 传入不同的动作。同时第 13 章的 Host 阀增加了一项检查：应用被停止后返回 503 Service Unavailable。

小结

  • Manager 应用通过描述符部署（privileged="true"），受 BASIC 认证保护，ManagerServlet 提供 list / start / stop / reload / undeploy 等文本命令。
  • 实现 ContainerServlet 的 Servlet 在加载时由 StandardWrapper 调用 setWrapper(this)，从而能访问 Context 和 Host（Deployer）。
  • 只有容器提供的、在特权应用中的 Servlet 才享有这一能力；它们必须由容器自己的类加载器加载。
  • 现代 Manager 拆分了角色、提供了文本 / HTML / JMX 三种接口，并默认只允许本机访问。
