第 16 章

关闭钩子

第 14 章的关闭端口很优雅——前提是用户愿意配合，乖乖发送 SHUTDOWN 命令。 可现实中的用户会直接关掉控制台、按 Ctrl+C、或者由运维脚本 kill 进程。 Java 的关闭钩子（shutdown hook）保证：无论 JVM 因为什么正常地退出，你的清理代码都有机会执行。

本章目标

  • 知道 JVM 在哪些情况下会关闭，以及关闭时的两个阶段
  • 会写、会注册关闭钩子，并理解它的局限
  • 理解 Tomcat 的 CatalinaShutdownHook 以及它和关闭端口的配合

JVM 什么时候关闭

写一个关闭钩子

关闭钩子就是一个 Thread 子类的实例。步骤：

  1. 写一个继承 Thread 的类，在 run() 里写清理代码；
  2. 创建它的实例；
  3. 调用 Runtime.getRuntime().addShutdownHook(hook) 注册。

注意：你不需要（也不能）自己调用它的 start()，JVM 关闭时会替你启动它。

public class ShutdownHookDemo {
    public void start() {
        System.out.println("Demo");
        ShutdownHook shutdownHook = new ShutdownHook();
        Runtime.getRuntime().addShutdownHook(shutdownHook);
    }
    public static void main(String[] args) {
        ShutdownHookDemo demo = new ShutdownHookDemo();
        demo.start();
        try {
            System.in.read();          // 按回车退出，退出时打印 "Shutting down"
        } catch (Exception e) {
        }
    }
}

class ShutdownHook extends Thread {
    public void run() {
        System.out.println("Shutting down");
    }
}

一个更实际的例子：删除临时文件

原书用一个 Swing 程序演示：启动时创建 temp.txt，退出时删除。如果用户点「Exit」按钮，shutdown() 会被调用；但如果点窗口右上角的 ×，或者从任务管理器结束进程，文件就留下了。解决办法是把 shutdown() 放进关闭钩子：

private void initialize() {
    MyShutdownHook shutdownHook = new MyShutdownHook();      // 内部类，可以调用外部类的 shutdown()
    Runtime.getRuntime().addShutdownHook(shutdownHook);
    File file = new File(dir, filename);
    System.out.println("Creating temporary file");
    file.createNewFile();
}

private class MyShutdownHook extends Thread {
    public void run() {
        shutdown();                                           // 删除 temp.txt
    }
}

Tomcat 的关闭钩子

org.apache.catalina.startup.Catalina（第 17 章）在启动 Server 时注册了一个关闭钩子：

protected class CatalinaShutdownHook extends Thread {
    public void run() {
        if (server != null) {
            try {
                ((Lifecycle) server).stop();       // 和收到 SHUTDOWN 命令后做的事一样
            } catch (LifecycleException e) {
                System.out.println("Catalina.stop: " + e);
                ...
            }
        }
    }
}
⚠ 关闭钩子的局限
  • 要快：操作系统关机、容器编排系统（如 Kubernetes 默认 30 秒）发出 SIGTERM 后只会等一段时间，超时就发 SIGKILL。
  • 并发执行、顺序不定：多个钩子同时运行，不要依赖彼此的先后，也要小心死锁。
  • 不能再注册钩子，也不要调用 System.exit()（会永久阻塞）。
  • 日志系统可能已经被别的钩子关掉了——Tomcat 的 JULI 专门做了处理：它的 ClassLoaderLogManager 会等 Catalina 的钩子跑完再关闭日志。

② 控制台版的临时文件程序

Swing 程序在没有图形界面的服务器上跑不起来，Java 17 版改成了控制台程序，并用 ProcessHandle.current().pid()（Java 9）打印进程号，方便用 kill 测试：

private static final Path TEMP = Path.of(System.getProperty("user.dir"), "temp.txt");

public static void main(String[] args) throws IOException {
    Runtime.getRuntime().addShutdownHook(new Thread(TempFileApp::shutdown, "cleanup-hook"));
    Files.writeString(TEMP, "pid=" + ProcessHandle.current().pid());    // Java 11 writeString
    System.out.println("按回车正常退出，或者在另一个终端执行 kill " + ProcessHandle.current().pid());
    System.in.read();
}

private static void shutdown() {
    try {
        if (Files.deleteIfExists(TEMP)) System.out.println("Deleting temporary file.");
    } catch (IOException e) {
        System.err.println("删除临时文件失败: " + e);
    }
}
💡 只是删除临时文件的话

JDK 自带 File.deleteOnExit()，内部就是一个关闭钩子。用 NIO 的话还可以 Files.newOutputStream(path, StandardOpenOption.DELETE_ON_CLOSE)，文件流关闭时就删除。

③ Catalina 风格的服务器钩子

StandardServer server = createServer(httpPort, shutdownPort);      // 第 14 章的整套组件
Thread hook = new Thread(() -> {
    System.out.println("CatalinaShutdownHook: JVM 正在退出，停止服务器");
    try {
        server.stop();
    } catch (LifecycleException e) {
        System.out.println("Catalina.stop: " + e);
    }
}, "CatalinaShutdownHook");

server.initialize();
server.start();
Runtime.getRuntime().addShutdownHook(hook);

server.await();                                   // 路径 A：收到 SHUTDOWN 才返回
Runtime.getRuntime().removeShutdownHook(hook);    // 正常关闭：移除钩子，避免 JVM 退出时再 stop 一次
server.stop();

④ 嵌入式 Tomcat 11 要自己注册钩子

独立部署的 Tomcat 由 Catalina 注册钩子（可以通过 Catalina 的 useShutdownHook 属性关闭）；用 Tomcat 类嵌入时没有 Catalina，需要自己注册，否则 kill 时 Servlet 的 destroy() 不会被调用、会话不会持久化：

Runtime.getRuntime().addShutdownHook(new Thread(() -> {
    try {
        tomcat.stop();
        tomcat.destroy();
    } catch (LifecycleException e) {
        e.printStackTrace();
    }
}, "TomcatShutdownHook"));
tomcat.start();
tomcat.getServer().await();

设计要点

这一章的代码里有几个可以带到别的项目里的设计决定。每条按「做法 → 取舍 → 替代方案 → 还能用在哪」来写；系统的讨论见设计篇。

1关闭钩子保证清理

Runtime.addShutdownHook 注册的线程在正常退出、Ctrl+C、SIGTERM 时都会执行。

取舍
kill -9 和断电时不会执行；钩子之间没有顺序保证，执行时间也不能太长。
还能用在
关闭连接池、刷写缓冲日志、注销服务发现；但关键数据要靠事务和持久化，不能依赖钩子。
延伸：第 32 章 · 并发、隔离与演进
2钩子只做一件事：调用 stop()

Catalina 的钩子只调用 server.stop()，具体清理逻辑仍在各组件的生命周期里。

取舍
清理逻辑只有一份，正常关闭和信号关闭走同一条路径。
还能用在
不要在钩子里写业务清理代码，把它放在组件的 close()/stop() 中。
延伸：第 29 章 · 整体架构：分层与边界
3stop() 要幂等

钩子和正常关闭流程可能先后调用 stop()。

取舍
多一个状态判断，换来重复调用不出错。
还能用在
所有 close()/shutdown() 方法都应该可以安全地调用多次。
延伸：第 32 章 · 并发、隔离与演进

小结

  • JVM 正常退出或被 Ctrl+C / SIGTERM 终止时，会先并发运行所有注册的关闭钩子；SIGKILL 和崩溃则不会。
  • 关闭钩子是一个未启动的 Thread，通过 Runtime.addShutdownHook 注册。
  • Catalina 的钩子调用 server.stop()，正常关闭路径会先移除钩子，保证 stop 只执行一次。
  • 钩子要快、不要依赖顺序、不要调用 System.exit()；嵌入式 Tomcat 需要自己注册钩子。

动手练习

  1. 注册两个钩子，分别 sleep 2 秒和 3 秒后打印，用 time 测量 kill 后进程多久退出，验证它们是并发运行的。
  2. 在钩子里调用 System.exit(0)，观察会发生什么（提示：用 jstack 看线程状态）。
  3. 给第 9 章的会话管理加上钩子：kill 进程后再启动，会话依然存在。
