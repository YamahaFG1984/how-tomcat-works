第 15 章

Digester

前面所有的启动类都是把组件「写死」在代码里：new 一个连接器，new 一个 Context，调一串 setter……改一个端口号都要重新编译。 真正的 Tomcat 把这些写在 server.xml 和 web.xml 里，靠一个叫 Digester 的库把 XML 元素变成 Java 对象。 这一章先学 Digester 的用法和原理，再看 ContextConfig 如何用它解析 web.xml、配置 Context。

本章目标

  • 理解 Digester 的三个核心概念：模式（pattern）、规则（rule）、对象栈
  • 会用 addObjectCreate、addSetProperties、addSetNext、addCallMethod、RuleSet
  • 亲手实现一个迷你 Digester，弄懂它在 SAX 事件上是怎么运转的
  • 理解 ContextConfig 的工作：解析默认 web.xml 和应用 web.xml、安装认证器、设置 configured

从硬编码到 XML 配置

Digester 原本是 Apache Jakarta Commons 的一个子项目（commons-digester.jar）。从 Tomcat 6 开始，Tomcat 把它复制进了自己的代码库，包名变成 org.apache.tomcat.util.digester，API 基本不变。

模式、规则与对象栈

模式（pattern）

根元素的模式就是元素名；子元素的模式是「父元素的模式 + / + 元素名」：

规则（rule）

规则由 Rule 类表示，最重要的两个方法是 begin（遇到开始标签时调用）和 end（遇到结束标签时调用）。Digester 内部用 Rules 对象保存「模式 → 规则列表」。常用的预定义规则：

方法规则类作用
addObjectCreate(pattern, className)ObjectCreateRulebegin：创建对象并压栈；end：出栈。也可以用属性（如 className）在运行时指定类名
addSetProperties(pattern)SetPropertiesRule把元素的每个属性 name="v" 变成栈顶对象的 setName("v")
addCallMethod(pattern, method)CallMethodRule调用栈顶对象的方法；带参数个数时，参数由子元素的 addCallParam 收集
addSetNext(pattern, method)SetNextRuleend：调用次栈顶对象的 method(栈顶对象)，建立父子关系

对象栈

Digester 内部有一个栈（原书比喻成一口井）。addObjectCreate 创建的对象被压进去，元素结束时弹出；addSetNext 在弹出之前把栈顶对象交给它下面的对象。下面是解析 employee2.xml 时栈的变化：

🔑 为什么 end 要倒着执行

同一个模式上注册了 ObjectCreate 和 SetNext 两条规则。结束标签时如果先执行 ObjectCreate.end（出栈），SetNext 就找不到要交给父对象的那个子对象了。所以 Digester 按注册顺序调用 begin，按相反顺序调用 end——这样「先创建的最后清理」，和栈的性质一致。

规则是怎么实现的

所有 addXxx 方法最终都调用 addRule(pattern, rule)。以 ObjectCreateRule 为例：

public void begin(Attributes attributes) throws Exception {
    String realClassName = className;
    if (attributeName != null) {                      // 允许 XML 里用属性指定类名
        String value = attributes.getValue(attributeName);
        if (value != null) realClassName = value;
    }
    Class clazz = digester.getClassLoader().loadClass(realClassName);
    Object instance = clazz.newInstance();
    digester.push(instance);
}

public void end() throws Exception {
    Object top = digester.pop();
}

// WrapperCreateRule：不是 new 一个固定的类，而是让栈底的 Context 创建 Wrapper
public void begin(Attributes attributes) throws Exception {
    Context context = (Context) digester.peek(digester.getCount() - 1);
    Wrapper wrapper = context.createWrapper();
    digester.push(wrapper);
}

② 迷你 Digester：SAX + 规则 + 栈

public interface Rule {                          // 三个回调都有默认空实现
    default void begin(MiniDigester digester, Attributes attributes) throws Exception { }
    default void body(MiniDigester digester, String text) throws Exception { }
    default void end(MiniDigester digester) throws Exception { }
}

public void addObjectCreate(String pattern, Supplier<?> factory) {   // 用构造器引用代替类名
    addRule(pattern, new Rule() {
        @Override public void begin(MiniDigester d, Attributes a) { d.push(factory.get()); }
        @Override public void end(MiniDigester d) { d.pop(); }
    });
}

public void addSetNext(String pattern, String methodName) {
    addRule(pattern, new Rule() {
        @Override public void end(MiniDigester d) throws Exception { invoke(d.peek(1), methodName, d.peek(0)); }
    });
}

@Override
public void startElement(String uri, String localName, String qName, Attributes attributes) {
    path.add(localName);
    bodies.push(new StringBuilder());
    forEachRule(rule -> rule.begin(this, attributes), false);
}

@Override
public void endElement(String uri, String localName, String qName) {
    String text = bodies.pop().toString();
    forEachRule(rule -> rule.body(this, text), false);
    forEachRule(rule -> rule.end(this), true);         // end 倒序
    path.remove(path.size() - 1);
}

③ 迷你 ContextConfig

static MiniDigester createWebDigester() {
    var digester = new MiniDigester();
    digester.addRule("web-app/servlet", new MiniDigester.Rule() {          // WrapperCreateRule
        @Override public void begin(MiniDigester d, Attributes a) { d.push(new SimpleWrapper()); }
        @Override public void end(MiniDigester d) { d.pop(); }
    });
    digester.addSetNext("web-app/servlet", "addChild");
    digester.addCallMethod("web-app/servlet/servlet-name", "setName", 0);
    digester.addCallMethod("web-app/servlet/servlet-class", "setServletClass", 0);
    digester.addCallMethod("web-app/servlet-mapping", "addServletMapping", 2);
    digester.addCallParam("web-app/servlet-mapping/url-pattern", 0);
    digester.addCallParam("web-app/servlet-mapping/servlet-name", 1);
    return digester;
}

private void applicationConfig(StandardContext context) {
    Path webXml = context.getDocBase().resolve("WEB-INF/web.xml");
    var digester = createWebDigester();
    digester.push(context);                      // 和原书一样：Context 压在栈底
    digester.parse(webXml);
}
ⓘ 现代 Tomcat 的 ContextConfig

Servlet 3.0 之后，一个应用的配置可能来自 web.xml、JAR 里的 web-fragment.xml、@WebServlet 等注解、ServletContainerInitializer。所以 Tomcat 7 起 ContextConfig 不再让 Digester 直接操作 Context，而是先把每个来源解析成一个 WebXml 对象（org.apache.tomcat.util.descriptor.web），按规则合并，最后调用 webXml.configureContext(context) 一次性配置。Digester 和 WebRuleSet 仍然在用，只是换了「栈底对象」。

设计要点

这一章的代码里有几个可以带到别的项目里的设计决定。每条按「做法 → 取舍 → 替代方案 → 还能用在哪」来写；系统的讨论见设计篇。

1声明式装配：XML 描述对象图

规则把元素映射为「创建对象」「设置属性」「调用方法」，server.xml 就成了一段装配程序的输入。

取舍
不重新编译就能改结构；代价是错误要到运行时才发现，IDE 难以导航。
替代方案
代码装配（嵌入式 Tomcat、Spring @Configuration）。
还能用在
任何需要由运维人员调整结构（而不仅是参数）的系统。
延伸：第 29 章 · 整体架构：分层与边界
2模式匹配 + 对象栈

每遇到一个元素就按路径模式找规则，创建的对象压栈，结束时出栈，父子关系由栈自然得到。

取舍
规则彼此独立，可以自由组合；但规则顺序和栈状态需要仔细考虑。
还能用在
任何树状配置（XML、JSON、YAML）到对象图的转换。
延伸：第 31 章 · 设计模式实战
3RuleSet：规则打包复用

ContextRuleSet、WebRuleSet 把一组规则打包，可以挂在不同前缀下。

取舍
规则可以模块化；代价是多一层间接。
还能用在
配置解析器按领域拆分成可复用的模块。
延伸：第 30 章 · 扩展点设计
4className 属性：每个组件都能换实现

server.xml 里几乎所有元素都接受 className，Digester 用它来实例化。

取舍
最强的扩展点——不改 Tomcat 就能替换任何组件；代价是没有类型检查，也增加了维护承诺。
还能用在
只在确实有替换需求的地方开放，并为替换实现提供契约和测试。
延伸：第 30 章 · 扩展点设计

小结

  • Digester 把 XML 元素按「模式 → 规则」转换成 Java 对象；规则通过一个对象栈协作。
  • 四个常用规则：ObjectCreate（创建并压栈）、SetProperties（属性 → setter）、SetNext（子对象交给父对象）、CallMethod/CallParam（调用方法）。
  • begin 按注册顺序执行，end 按相反顺序执行；RuleSet 把一组规则打包复用。
  • ContextConfig 是 StandardContext 必需的监听器：解析默认和应用 web.xml、安装认证器阀，最后设置 configured。
  • WebRuleSet 把 <servlet> 变成 Wrapper，把 <servlet-mapping> 变成 addServletMapping；现代 Tomcat 先解析成 WebXml 再合并配置。

动手练习

  1. 给 MiniDigester 增加 addObjectCreate(pattern, defaultClass, attributeName)：如果元素上有 className 属性，就按它创建对象（反射），否则用默认类。
  2. 扩展迷你 ContextConfig，支持 <init-param>（配合第 11 章的 StandardWrapper）和 <session-config><session-timeout>。
  3. 用 MiniDigester 解析一个精简版 server.xml（Server / Service / Connector / Engine / Host / Context），直接搭出第 14 章的整套组件——这正是第 17 章 Catalina 类做的事。
