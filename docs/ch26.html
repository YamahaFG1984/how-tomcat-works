TLS、HTTP/2 与 WebSocket

原书里的连接器只说一种语言：明文的 HTTP/1.1，一问一答。今天的 Tomcat 还要处理加密（TLS）、 在一个连接上并行跑几十个请求（HTTP/2），以及把一个 HTTP 连接「升级」成双向的消息通道（WebSocket）。 这三者有一个共同点：它们都发生在连接器这一层，到了容器里，Servlet 几乎感觉不到区别。 本章各写一个能跑的例子，其中 WebSocket 服务器不依赖任何库，从握手到帧格式全部手写。

本章目标

  • 知道 TLS 在 Tomcat 里配置在哪里，SNI 和 ALPN 分别解决什么问题
  • 理解 HTTP/2 的多路复用，以及 Tomcat 如何把每个「流」当作一个普通请求交给容器
  • 掌握 WebSocket 的握手和帧格式，能读懂 Sec-WebSocket-Accept 是怎么算出来的
  • 理解 HTTP 升级机制（HttpServletRequest.upgrade）如何让一个连接离开 Servlet 管道

TLS：加密发生在连接器里

HTTPS 就是在 TCP 和 HTTP 之间加一层 TLS。对 Tomcat 来说，它是连接器的一个属性： 同一个 NioEndpoint，读写 socket 时多一步加解密（SecureNioChannel 包装了 SSLEngine）。 容器只能通过 request.isSecure()、getScheme() 和一些请求属性（客户端证书、加密套件）知道这是一个 HTTPS 请求。

  • SNI（Server Name Indication）：一个 IP 上托管多个 HTTPS 域名时，服务器得在发证书之前知道客户端要访问哪个域名。客户端把域名明文放在 ClientHello 里，Tomcat 按它选择 <SSLHostConfig hostName="…">。这是第 13 章「虚拟主机」在 TLS 层的对应物。
  • ALPN（Application-Layer Protocol Negotiation）：客户端列出自己会说的协议，服务器挑一个。浏览器只通过 ALPN 使用 HTTP/2，所以「HTTP/2 必须配 HTTPS」在实践中是成立的。
💡 JSSE 还是 OpenSSL？

Tomcat 默认用 JDK 自带的 JSSE 实现 TLS，线程名里的 https-jsse-nio-8443-exec-1 就是这个意思。 也可以换成 OpenSSL（以前通过 tomcat-native 库，Tomcat 11 在 Java 22+ 上还能通过 FFM API 直接调用），握手性能更好。 配置方式相同，都是 SSLHostConfig。很多部署干脆让前面的 Nginx 或云负载均衡器终结 TLS，Tomcat 只跑明文。

HTTP/2：一个连接，多个流

HTTP/1.1 的 keep-alive 让连接可以复用，但一个连接上同一时刻只能有一个请求在跑，后面的必须排队（队头阻塞）。 浏览器的办法是对同一个域名开 6 个连接。HTTP/2 换了思路：报文被切成二进制帧，每帧标明属于哪个流（stream）， 不同流的帧可以在一个连接上交错发送：

在 Tomcat 里开启 HTTP/2 只需要给连接器加一个升级协议：<UpgradeProtocol className="org.apache.coyote.http2.Http2Protocol"/>。 它支持两种进入方式：HTTPS 上通过 ALPN 协商（h2），明文上通过 Upgrade: h2c 头或者「直接说 HTTP/2」（prior knowledge）。 第 23 章那张 Coyote 分层图在这里体现了价值：HTTP/2 复用了 NioEndpoint 和 CoyoteAdapter，只替换了中间的 Processor。

⚠️ 服务器推送已经退场

HTTP/2 曾经有「服务器推送」：服务器主动把客户端还没请求的资源推过去（Servlet 4.0 的 PushBuilder）。 实践证明它很难用好，主流浏览器已移除支持，Servlet 6.1 也将其标记为废弃。现在的替代方案是 103 Early Hints 和 <link rel="preload">。

WebSocket：从 HTTP 升级出来的双向通道

第 24 章的 SSE 只能服务器往客户端推。聊天、协同编辑、游戏需要双向、低延迟的消息，这就是 WebSocket。 它的巧妙之处在于开场：先发一个普通的 HTTP 请求，双方同意之后，同一个 TCP 连接就改说另一种协议。

Sec-WebSocket-Accept 的计算不是为了安全，而是为了确认「对方真的懂 WebSocket」： 一个不懂的普通 HTTP 服务器不可能碰巧回出正确的值。上图里的 Key 和 Accept 是 RFC 6455 给出的标准例子，本章用 Tomcat 验证过。 握手之后，数据以帧为单位传输：

在 Tomcat 里：升级让连接离开 Servlet 管道

Servlet 3.1 提供了通用的升级 API：request.upgrade(MyHandler.class)。调用它的 Servlet 或过滤器写完 101 响应后， 这个连接就不再按 HTTP 解析了，连接器会把之后的数据交给 HttpUpgradeHandler。Tomcat 的 WebSocket 实现就建立在它之上：

  1. WsSci（第 25 章的 SCI 机制）在应用启动时创建 WsServerContainer，注册所有 @ServerEndpoint，并装上过滤器 WsFilter。
  2. 握手请求和普通请求一样走完第 23 章那张栈：连接器 → CoyoteAdapter → Engine → Host → Context → 过滤器链。
  3. WsFilter 发现这是一个指向已注册端点的握手请求，校验头部、计算 Accept，调用 request.upgrade(WsHttpUpgradeHandler.class)。
  4. 请求处理结束后，连接器发现「已升级」，把这个 socket 交给 WsHttpUpgradeHandler。之后每当 Poller 发现数据可读，就由它解析帧并回调 @OnMessage。
🔑 一个踩到的坑：没有 Servlet 就没有过滤器

本章的 Tomcat 示例第一版返回了 404。原因是第 12 章的映射规则：请求必须先映射到某个 Wrapper，StandardContextValve 才会构建过滤器链；Context 里一个 Servlet 都没有时，请求在到达 WsFilter 之前就被判为 404。 普通 Web 应用有 DefaultServlet 兜底（第 22 章），所以遇不到。修复办法就是加一个映射到 / 的 DefaultServlet。

① 手写 WebSocket：握手

static final String GUID = "258EAFA5-E914-47DA-95CA-C5AB0DC85B11";   // RFC 6455 规定的常量

static String acceptKey(String key) {
    byte[] sha1 = MessageDigest.getInstance("SHA-1").digest((key + GUID).getBytes(ISO_8859_1));
    return Base64.getEncoder().encodeToString(sha1);
}

out.write(("HTTP/1.1 101 Switching Protocols\r\n"
        + "Upgrade: websocket\r\nConnection: Upgrade\r\n"
        + "Sec-WebSocket-Accept: " + acceptKey(key) + "\r\n\r\n").getBytes(ISO_8859_1));
// 从这里开始，同一个 socket 上读写的都是帧

② 手写 WebSocket：读一帧

record Frame(boolean fin, int opcode, boolean masked, byte[] payload) {

    static Frame read(DataInputStream in) throws IOException {
        int b0 = in.readUnsignedByte();
        int b1 = in.readUnsignedByte();
        boolean fin = (b0 & 0x80) != 0;
        int opcode = b0 & 0x0F;
        boolean masked = (b1 & 0x80) != 0;
        long len = b1 & 0x7F;
        if (len == 126) len = in.readUnsignedShort();
        else if (len == 127) len = in.readLong();
        byte[] mask = new byte[4];
        if (masked) in.readFully(mask);
        byte[] payload = new byte[(int) len];
        in.readFully(payload);
        if (masked) {
            for (int i = 0; i < payload.length; i++) payload[i] ^= mask[i % 4];
        }
        return new Frame(fin, opcode, masked, payload);
    }
}

③ Tomcat：注解式端点

@ServerEndpoint("/chat")
public class ChatEndpoint {                         // 每个连接一个实例

    private static final Set<Session> SESSIONS = new CopyOnWriteArraySet<>();

    @OnOpen
    public void onOpen(Session session) {
        SESSIONS.add(session);
        broadcast("系统：" + session.getId() + " 加入，当前 " + SESSIONS.size() + " 人");
    }

    @OnMessage
    public void onMessage(String message, Session session) {
        broadcast(session.getId() + "：" + message);
    }

    private static void broadcast(String text) {
        for (Session s : SESSIONS) {
            synchronized (s) {                      // 同一个会话不允许并发发送
                s.getBasicRemote().sendText(text);
            }
        }
    }
}

Tomcat.addServlet(ctx, "default", new DefaultServlet());     // 没有它，握手请求到不了 WsFilter
ctx.addServletMappingDecoded("/", "default");
ctx.addServletContainerInitializer(new WsSci(), null);        // 创建 ServerContainer、装 WsFilter
ctx.addServletContainerInitializer((classes, sc) -> {
    var container = (ServerContainer) sc.getAttribute(ServerContainer.class.getName());
    container.addEndpoint(ChatEndpoint.class);                 // 相当于扫描到 @ServerEndpoint
}, null);

④ Tomcat：HTTPS + HTTP/2

var https = new Connector();                                  // 默认 HTTP/1.1 NIO
https.setPort(8443);
https.setScheme("https");
https.setSecure(true);
https.setProperty("SSLEnabled", "true");
var ssl = new SSLHostConfig();                                // 可以有多个，按 SNI 主机名选择
var cert = new SSLHostConfigCertificate(ssl, SSLHostConfigCertificate.Type.RSA);
cert.setCertificateKeystoreFile(keystore.toString());         // 启动时用 keytool 生成的自签名证书
cert.setCertificateKeystorePassword("changeit");

https.addSslHostConfig(ssl);
https.addUpgradeProtocol(new Http2Protocol());                // TLS + ALPN 协商 h2
tomcat.getService().addConnector(https);

tomcat.getConnector().addUpgradeProtocol(new Http2Protocol());  // 明文 8080 也支持 h2c

设计要点

这一章的代码里有几个可以带到别的项目里的设计决定。每条按「做法 → 取舍 → 替代方案 → 还能用在哪」来写；系统的讨论见设计篇。

1新协议作为「升级」挂到旧协议上

HTTP/2 和 WebSocket 都从 HTTP/1.1 连接升级而来，Tomcat 用 UpgradeProtocol / HttpUpgradeHandler 承接，复用同一个 Endpoint。

取舍
不需要新端口，能穿过只认 HTTP 的防火墙和代理，老客户端照常工作；代价是握手多一个往返，协议实现要处理「升级前」和「升级后」两种状态。
还能用在
协议版本协商（客户端声明支持的版本，服务器挑一个）、数据库驱动的能力协商、API 的内容协商（Accept 头）。
延伸：第 32 章 · 并发、隔离与演进
2把新东西翻译成旧接口

HTTP/2 的每个流被包装成一个普通请求，经 CoyoteAdapter 交给容器，Servlet 不用改一行代码。

取舍
生态里所有过滤器、框架都直接受益；代价是旧接口表达不了新能力（流优先级、推送），只能另开 API 或放弃。
还能用在
引入新的消息中间件时，先实现旧的消费者接口；新存储引擎先兼容旧的 DAO 接口，再逐步暴露新特性。
延伸：第 29 章 · 整体架构：分层与边界
3握手里验证「对方真的懂」

WebSocket 用 Key + 固定 GUID 的 SHA-1 证明服务器理解协议；客户端帧加掩码防止被代理误解。

取舍
几行代码的成本，换来与不懂协议的中间设备之间不会产生歧义；它不是认证，安全仍要靠 TLS 和应用层鉴权。
还能用在
自定义协议的魔数和版本号、文件格式的签名头：开场先确认双方说的是同一种语言。
4边界处终结复杂度

TLS 可以在 Tomcat 终结，也常常交给前面的负载均衡器；无论哪种，容器只通过 isSecure() 感知。

取舍
证书和加密集中管理，应用服务器更简单；代价是负载均衡器到 Tomcat 之间是明文，需要 RemoteIpValve 读取 X-Forwarded-Proto 才能得到正确的 isSecure()。
还能用在
API 网关统一做鉴权、限流、协议转换，后端服务只处理业务。
延伸：第 28 章 · 运维：调优、监控与加固

小结

  • TLS 是连接器的属性：SSLHostConfig 配置证书，SNI 用来选证书，ALPN 用来选 HTTP 版本。
  • HTTP/2 用帧和流实现多路复用；Tomcat 通过 Http2Protocol 升级协议支持 h2 和 h2c，每个流作为一个普通请求交给容器。
  • WebSocket 从一次 HTTP 握手开始（101 + Sec-WebSocket-Accept），之后同一连接上交换带掩码的帧。
  • Tomcat 的 WebSocket 由 WsSci 启动、WsFilter 握手、request.upgrade() 让连接离开 Servlet 管道。

动手练习

  1. 给 MiniWebSocketServer 加上分片支持：收到 fin=false 的文本帧时先缓存，直到 fin=true 的续帧到达再拼成完整消息。
  2. 用 keytool 再生成一张 CN=example.test 的证书，给 HTTPS 连接器加第二个 SSLHostConfig(hostName="example.test")，用 curl -k --resolve example.test:8443:127.0.0.1 https://example.test:8443/info -v 观察服务器返回了哪张证书。
  3. 把 Http2Client 改成 HttpClient.Version.HTTP_1_1，比较 20 个请求的总耗时和客户端端口数量。
  4. 给聊天室加一个心跳：服务器每 10 秒给每个会话发一个 ping，30 秒内没有收到 pong 就关闭会话。
