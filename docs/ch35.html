自测题

第一、二部分：起步与连接器（第 1～4 章）

  1. 第 1 章的服务器为什么一次只能服务一个客户端？
    看答案

    accept、读请求、写响应、关闭连接都在同一个线程里串行执行，处理一个连接期间不会调用下一次 accept。

  2. 容器为什么把 RequestFacade 而不是 Request 交给 Servlet？
    看答案

    Request 为了让同包的类使用，有 parse()、recycle() 等公开方法；Servlet 拿到它可以向下转型调用，破坏容器的状态。外观只暴露规范接口里的方法。

  3. 连接器和容器之间的接口是什么？为什么要这样分开？
    看答案

    容器的 invoke(request, response)（今天是 CoyoteAdapter 调用 Engine 管道）。协议和 IO 模型与业务处理按不同的原因、在不同的时间变化，分开后可以各自替换。

  4. 请求参数为什么要懒解析？有什么副作用？
    看答案

    不需要参数的请求不必付出解析成本。副作用是解析时机会影响结果：如果先读了 getInputStream()，表单参数就再也解析不出来了。

  5. 第 4 章的处理器池满了会发生什么？今天的 Tomcat 呢？
    看答案

    第 4 章直接关闭新连接。今天：工作线程满了任务在线程池里排队；连接数到 maxConnections 时 Acceptor 暂停接收，连接留在内核 backlog；backlog（acceptCount）也满了，内核拒绝或丢弃新连接。

第三部分：容器的组件（第 5～10 章）

  1. 基础阀和附加阀有什么区别？
    看答案

    基础阀由容器自己设置，总在管道最后，负责把请求交给下一层容器或调用 Servlet；附加阀可以任意增删，可以在后续处理前后做事，也可以短路。

  2. WebappClassLoader 为什么要打破双亲委派？为什么又不能完全打破？
    看答案

    让应用自带的库优先于容器的库，实现应用之间的隔离和重载。但 java.* 和 Servlet API 必须交给父加载器，否则同名接口会被加载两次，容器和应用看到的就不是同一个类型，同时也防止应用替换核心类。

  3. 过期的会话是怎么被清理的？
    看答案

    两种方式结合：访问时检查是否过期；后台线程定期扫描所有会话（今天由 backgroundProcess 驱动 Manager 的 processExpires）。

  4. Authenticator 和 Realm 各负责什么？为什么要分开？
    看答案

    Authenticator 决定怎样向用户要凭据（BASIC、FORM、DIGEST），Realm 负责校验凭据和查询角色（内存、JDBC、LDAP）。分开后两个维度可以任意组合。

  5. 生命周期为什么要从一个 started 布尔值演变成状态枚举？
    看答案

    布尔值表达不了「启动中」「停止中」「失败」这些阶段，也无法拒绝非法的转换。枚举状态机把合法转换集中定义，并能给出清晰的错误。

第四部分：标准实现（第 11～14 章）

  1. SingleThreadModel 为什么被移除？
    看答案

    它只保证同一个实例不被并发调用，静态变量、会话、外部资源仍然是共享的，给了开发者虚假的安全感；实例池还限制了吞吐。

  2. Servlet 映射的四条规则是什么？按什么顺序？
    看答案

    精确匹配 → 最长路径前缀（/a/*）→ 扩展名（*.do）→ 默认 Servlet（/）。

  3. Tomcat 5 起周期性后台工作是怎样组织的？
    看答案

    Engine 上的一个后台线程定期调用 backgroundProcess()，每个容器处理自己的事（Loader 检查修改、Manager 清理会话），再递归调用子容器。取代了每个组件各开一个线程的做法。

  4. StandardService 为什么先启动 Engine 再启动 Connector？
    看答案

    保证连接器开始接收请求时，容器已经就绪；停止时反过来，先停止接收再拆除容器，不会有请求打到半初始化或正在关闭的容器上。

第五部分：启动、部署与管理（第 15～20 章）

  1. Digester 用什么建立对象之间的父子关系？
    看答案

    一个对象栈：遇到元素时按规则创建对象并压栈，SetNextRule 在元素结束时把栈顶对象交给下面那个对象（例如 addChild），然后出栈。

  2. 关闭钩子在什么情况下不会执行？
    看答案

    kill -9、断电、JVM 崩溃或调用 Runtime.halt()。所以关键数据不能只依赖关闭钩子保存。

  3. Bootstrap 为什么用反射调用 Catalina？
    看答案

    Catalina 及容器的类由 Bootstrap 创建的 server 类加载器加载，不在系统类路径上；Bootstrap 自己编译时不能直接引用它们。这样 Web 应用也看不到容器的内部类。

  4. 标准 MBean 和模型 MBean 的区别？
    看答案

    标准 MBean 要求被管理的类实现一个 XxxMBean 接口；模型 MBean 用外部描述符（如 mbeans-descriptors.xml）描述可管理的属性和操作，被管理的类不需要修改。

第六部分：现代 Servlet 容器（第 21～28 章）

  1. forward 和 include 在路径信息和响应上有什么区别？
    看答案

    forward：目标看到的是目标路径（原路径在 forward.* 属性里），之前写的内容被清空，返回后响应关闭。include：目标看到的仍是原路径（目标路径在 include.* 属性里），只能写响应体，不能改状态码和响应头。

  2. 表单提交的中文为什么容易乱码？怎么修？
    看答案

    浏览器提交表单时通常不在 Content-Type 里写 charset，规范默认用 ISO-8859-1 解码请求体。修复：在 web.xml 声明 <request-character-encoding>UTF-8，或在第一次读参数之前调用 setCharacterEncoding("UTF-8")。

  3. NIO 连接器为什么扛得住慢客户端？它解决不了什么？
    看答案

    等数据时不占线程：Selector 监视所有连接，数据不完整时 Worker 立即归还，读到一半的状态保存在 SocketWrapper 里。它解决不了业务本身慢——请求进入 Servlet 后线程仍被占到 service() 返回。

  4. startAsync() 后把阻塞的 JDBC 调用提交给自己的线程池，有收益吗？
    看答案

    容器线程省下了，但业务线程池里的线程依然阻塞，只是换了地方排队。真正的收益来自等待本身不占线程：定时器、回调、异步客户端，或者虚拟线程。

  5. metadata-complete="true" 会关闭 SCI 吗？
    看答案

    不会。它只跳过注解扫描和 web-fragment.xml；SCI 及其 @HandlesTypes 扫描照常进行（第 25 章做过实验）。要排除 jar 的 SCI，用 <absolute-ordering> 或 containerSciFilter。

  6. 什么是虚拟线程的钉住？
    看答案

    虚拟线程阻塞时本应卸载、让出载体线程；但在 synchronized 中阻塞（JDK 21～23）或在本地调用中阻塞时无法卸载，载体线程被一起占住。JDK 24 的 JEP 491 解决了前一种情况。

  7. ThreadLocal 为什么会导致应用重载后的内存泄漏？
    看答案

    容器线程比应用活得久。线程的 ThreadLocalMap 对值是强引用，如果值的类来自应用的类加载器，就形成「线程 → 值 → 类 → 类加载器」的链，整个旧应用都无法回收。

第七部分：设计篇（第 29～32 章）

  1. 怎样判断一个系统做到了「配置、装配、运行分离」？
    看答案

    组件里没有解析配置的代码，也不 new 自己的依赖；同一个对象图既能由配置文件生成，也能在测试里用代码直接装配。

  2. 拦截链、事件监听、策略插槽分别适合什么需求？
    看答案

    需要修改、阻止或包住一次调用 → 拦截链；只需要在某件事发生时得到通知 → 监听；要把一整块能力换成另一种实现 → 策略插槽。实现来自第三方时再配合发现机制。

  3. 外观、适配器、装饰器的区别？
    看答案

    都是「包一层」：外观让接口变少，适配器让接口变样，装饰器接口不变但增加行为。

  4. 舱壁模式解决什么问题？代价是什么？
    看答案

    慢的工作占满共享线程池，拖慢本来很快的工作。给不同类别的工作分配各自的池可以隔离影响；代价是资源可能闲置，总容量不能互相借用。

  5. 什么是「三次法则」？
    看答案

    第三次遇到同类需求时才抽象出公开的扩展点，那时手里有三个真实的例子；在那之前只保留一个内部接缝（例如集中的工厂方法），以后要开放时只改一处。

第八部分：综合与练习（第 33～34 章）

  1. 为什么 Engine 的阀第一次被调用时，Wrapper 就已经确定了？
    看答案

    现代 Tomcat 在 CoyoteAdapter.postParseRequest 里用全局的 Mapper 一次性映射出 Host、Context、Wrapper，原书中逐层映射的做法已经被替换。

  2. 调度器的拦截器顺序从 retry, timeout 改成 timeout, retry，语义有什么变化？
    看答案

    前者 timeout 在 retry 内层，每次尝试各有一个超时；后者 timeout 在外层，所有重试加起来共享一个超时。

  3. 调度器停机时为什么要放弃重试？
    看答案

    停机要在宽限期内尽快收尾；任务已经不可用，再发起新尝试只会拖长停机或在宽限期结束时被强行中断。在途的那一次允许执行完，但不再开始新的。
