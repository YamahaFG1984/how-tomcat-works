第 6 章

生命周期

Catalina 由许多组件组成：连接器、容器、载入器、会话管理器、日志记录器…… 启动时它们都要启动，关闭时都要有机会清理（调用 Servlet 的 destroy、把会话存盘）。 Lifecycle 接口让这一切变成「启动一个，全部启动；停止一个，全部停止」， 同时提供了一套事件机制，让别的组件可以在启动、停止的各个时刻插一脚。

本章目标

  • 理解 Lifecycle、LifecycleEvent、LifecycleListener 三个类型
  • 看懂 LifecycleSupport 的写时复制技巧
  • 理解父组件如何级联启动、停止子组件，以及六个事件的触发时机
  • 了解 Tomcat 7 以后的 LifecycleBase 状态机

一键启停

Catalina 的设计是：除了最顶层的一个组件，每个组件都被「托管」给一个父组件，由父组件负责启动和停止它。这样启动类只需要启动一个组件：

三个核心类型

Lifecycle 接口

public interface Lifecycle {
    public static final String START_EVENT = "start";
    public static final String BEFORE_START_EVENT = "before_start";
    public static final String AFTER_START_EVENT = "after_start";
    public static final String STOP_EVENT = "stop";
    public static final String BEFORE_STOP_EVENT = "before_stop";
    public static final String AFTER_STOP_EVENT = "after_stop";

    public void addLifecycleListener(LifecycleListener listener);
    public LifecycleListener[] findLifecycleListeners();
    public void removeLifecycleListener(LifecycleListener listener);
    public void start() throws LifecycleException;
    public void stop() throws LifecycleException;
}

最重要的是 start 和 stop；另外三个方法管理监听器；六个常量是六种事件的名字。

LifecycleEvent 与 LifecycleListener

public final class LifecycleEvent extends EventObject {
    public LifecycleEvent(Lifecycle lifecycle, String type, Object data) { ... }
    public Object getData()        { return this.data; }      // 附加数据，通常为 null
    public Lifecycle getLifecycle() { return this.lifecycle; } // 事件源
    public String getType()        { return this.type; }      // "start"、"stop" ……
}

public interface LifecycleListener {
    public void lifecycleEvent(LifecycleEvent event);
}

六个事件的时间线

LifecycleSupport：写时复制

每个实现 Lifecycle 的组件都要自己存监听器、实现三个监听器方法、遍历调用——这些重复代码被抽到了工具类 org.apache.catalina.util.LifecycleSupport 里。它的实现很有意思：

private LifecycleListener listeners[] = new LifecycleListener[0];

public void addLifecycleListener(LifecycleListener listener) {
    synchronized (listeners) {
        LifecycleListener results[] = new LifecycleListener[listeners.length + 1];
        for (int i = 0; i < listeners.length; i++)
            results[i] = listeners[i];
        results[listeners.length] = listener;
        listeners = results;                     // 换成新数组
    }
}

public void fireLifecycleEvent(String type, Object data) {
    LifecycleEvent event = new LifecycleEvent(lifecycle, type, data);
    LifecycleListener interested[] = null;
    synchronized (listeners) {
        interested = (LifecycleListener[]) listeners.clone();   // 先拍快照
    }
    for (int i = 0; i < interested.length; i++)
        interested[i].lifecycleEvent(event);                    // 在快照上遍历
}

组件只需持有一个 LifecycleSupport 并把调用转发给它：

protected LifecycleSupport lifecycle = new LifecycleSupport(this);

public void addLifecycleListener(LifecycleListener listener) {
    lifecycle.addLifecycleListener(listener);
}
...
lifecycle.fireLifecycleEvent(START_EVENT, null);

本章应用

应用基于第 5 章的 Context 应用（为简化去掉了两个日志阀）。SimpleContext、SimpleWrapper、SimpleLoader、SimplePipeline 都实现了 Lifecycle，另外新增一个监听器 SimpleContextLifecycleListener。

SimpleContext.start / stop

public synchronized void start() throws LifecycleException {
    if (started)
        throw new LifecycleException("SimpleContext has already started");
    lifecycle.fireLifecycleEvent(BEFORE_START_EVENT, null);
    started = true;
    try {
        if ((loader != null) && (loader instanceof Lifecycle))
            ((Lifecycle) loader).start();                  // ① 载入器
        Container children[] = findChildren();
        for (int i = 0; i < children.length; i++) {
            if (children[i] instanceof Lifecycle)
                ((Lifecycle) children[i]).start();         // ② 子容器
        }
        if (pipeline instanceof Lifecycle)
            ((Lifecycle) pipeline).start();                // ③ 管道
        lifecycle.fireLifecycleEvent(START_EVENT, null);
    } catch (Exception e) {
        e.printStackTrace();
    }
    lifecycle.fireLifecycleEvent(AFTER_START_EVENT, null);
}

public void stop() throws LifecycleException {
    if (!started)
        throw new LifecycleException("SimpleContext has not been started");
    lifecycle.fireLifecycleEvent(BEFORE_STOP_EVENT, null);
    lifecycle.fireLifecycleEvent(STOP_EVENT, null);
    started = false;
    // 按相反顺序停止：管道 → 子容器 → 载入器
    ...
    lifecycle.fireLifecycleEvent(AFTER_STOP_EVENT, null);
}

SimpleWrapper.stop：Servlet 的最后一程

Wrapper 停止时最重要的一件事是调用 Servlet 的 destroy()——第 2 章讲的 Servlet 生命周期，终于在这里完整了：

public void stop() throws LifecycleException {
    System.out.println("Stopping wrapper " + name);
    try {
        instance.destroy();          // Servlet 生命周期的最后一步
    } catch (Throwable t) {
    }
    instance = null;
    if (!started)
        throw new LifecycleException("Wrapper " + name + " not started");
    lifecycle.fireLifecycleEvent(BEFORE_STOP_EVENT, null);
    lifecycle.fireLifecycleEvent(STOP_EVENT, null);
    started = false;
    ...
    lifecycle.fireLifecycleEvent(AFTER_STOP_EVENT, null);
}

监听器与启动类

public class SimpleContextLifecycleListener implements LifecycleListener {
    public void lifecycleEvent(LifecycleEvent event) {
        Lifecycle lifecycle = event.getLifecycle();
        System.out.println("SimpleContextLifecycleListener's event " + event.getType().toString());
        if (Lifecycle.START_EVENT.equals(event.getType())) {
            System.out.println("Starting context.");
        } else if (Lifecycle.STOP_EVENT.equals(event.getType())) {
            System.out.println("Stopping context.");
        }
    }
}

② 手写写时复制 → CopyOnWriteArrayList

private final List<LifecycleListener> listeners = new CopyOnWriteArrayList<>();

public void addLifecycleListener(LifecycleListener listener) {
    listeners.add(listener);                 // 内部就是「复制新数组 + 替换引用」
}

public void fireLifecycleEvent(LifecycleEvent.Type type, Object data) {
    var event = new LifecycleEvent(lifecycle, type, data);
    for (LifecycleListener listener : listeners) {    // 迭代器天然遍历快照
        listener.lifecycleEvent(event);
    }
}

    if (component instanceof Lifecycle lifecycle) {

此外，LifecycleListener 是函数式接口，启动类里直接用 lambda 注册了第二个监听器：

context.addLifecycleListener(new SimpleContextLifecycleListener());

④ 现代 Tomcat：LifecycleBase 状态机

原书中每个组件都要自己维护 started 布尔值、自己检查重复启动、自己按顺序发三个事件——同样的代码到处复制。Tomcat 7 把它重构成了模板方法 + 状态机：抽象类 LifecycleBase 实现 init/start/stop/destroy，负责状态检查和发事件，子类只需实现 initInternal/startInternal/stopInternal/destroyInternal。

EmbeddedLifecycle 给 Tomcat 11 的 Context 注册了一个监听器，启动、停止、销毁整个服务器，打印 Context 收到的事件和状态。你会看到新增的 before_init/after_init、configure_start/configure_stop、before_destroy/after_destroy 等事件：

Context context = tomcat.addContext("", null);
context.addLifecycleListener((LifecycleEvent event) -> {
    if (!Lifecycle.PERIODIC_EVENT.equals(event.getType())) {     // 过滤掉后台线程的周期事件（第 12 章）
        System.out.printf("  %-22s state=%s%n", event.getType(), event.getLifecycle().getState());
    }
});
tomcat.start();
tomcat.stop();
tomcat.destroy();

设计要点

这一章的代码里有几个可以带到别的项目里的设计决定。每条按「做法 → 取舍 → 替代方案 → 还能用在哪」来写；系统的讨论见设计篇。

1统一生命周期，级联启动

所有组件实现 Lifecycle；父组件 start() 时先启动自己的子组件，所以只要启动顶层。

取舍
每个组件都要写 start/stop，但启动和关闭顺序不再需要人工记忆。
替代方案
启动脚本里手动按顺序 new 和 init（组件越多越容易漏）。
还能用在
Spring SmartLifecycle、Guava Service；任何持有线程、连接、文件句柄的模块都应有明确的 start/stop。
延伸：第 29 章 · 整体架构：分层与边界
2观察者：用监听器挂载行为

LifecycleListener 在 BEFORE_START、START、AFTER_START 等事件上被通知。

取舍
不修改组件就能扩展它（第 15 章的 ContextConfig 就是一个监听器）；代价是控制流变得隐式。
还能用在
领域事件、插件钩子；监听器里不要做太重的事，也不要依赖监听器之间的顺序。
延伸：第 31 章 · 设计模式实战
3组合优于继承：LifecycleSupport

监听器的注册、遍历、通知集中在 LifecycleSupport，组件持有它并委托调用。

取舍
多一个字段，换来不占用唯一的父类位置。Java 17 版用 CopyOnWriteArrayList，遍历时增删监听器也安全。
替代方案
抽象基类（Tomcat 后来的 LifecycleBase）。
还能用在
通用能力（事件、指标、重试）做成可组合的辅助对象，而不是塞进继承树。
延伸：第 31 章 · 设计模式实战
4关闭顺序与启动顺序相反

先启动被依赖者（Loader、Manager），再启动依赖者；关闭时倒过来。

取舍
保证任何组件在运行期间，它依赖的组件都可用。
还能用在
资源释放按 LIFO：try-with-resources、Spring 的 bean 销毁顺序都是这样。
延伸：第 32 章 · 并发、隔离与演进
5布尔标志 → 状态机

原书只有一个 started 布尔值；Tomcat 7 引入 LifecycleState 枚举，明确每个状态允许哪些转换。

取舍
状态机多写一些代码，但能拒绝非法转换（例如在 STARTING 时调用 stop），并给出清晰的错误。
还能用在
一个对象有两个以上布尔标志描述「阶段」时，就该换成枚举状态机。
延伸：第 32 章 · 并发、隔离与演进

小结

  • Lifecycle 让父组件统一启停子组件，启动类只需启停最顶层的一个组件。
  • 启动时依次触发 before_start → start → after_start，停止时 before_stop → stop → after_stop；停止顺序与启动顺序相反。
  • LifecycleSupport 用写时复制数组保存监听器，等价于 CopyOnWriteArrayList。
  • Wrapper 停止时调用 Servlet.destroy()，Servlet 生命周期至此完整。
  • Tomcat 7+ 用 LifecycleBase + LifecycleState 状态机消除了各组件中的重复代码，并增加了 init/destroy 阶段。

动手练习

  1. 在 Java 17 版里连续调用两次 context.start()，观察抛出的异常。
  2. 写一个监听器，在 AFTER_START 时调用所有 Wrapper 的 allocate()，实现「启动时预加载 Servlet」（这就是 web.xml 里 load-on-startup 的效果）。
  3. 在监听器回调里调用 removeLifecycleListener(this) 注销自己。把 CopyOnWriteArrayList 换成 ArrayList 再试一次，解释为什么会抛 ConcurrentModificationException。
  4. 仿照 Tomcat 的 LifecycleBase，写一个抽象类：用一个 LifecycleState 枚举代替 started 布尔值，start() 负责状态检查和发事件，子类只实现 startInternal()。
