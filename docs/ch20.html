第 20 章

基于 JMX 的管理

第 19 章的 ContainerServlet 能管理 Tomcat，但它把管理能力绑死在一个 Servlet 上。 JMX（Java Management Extensions）是一个更通用的标准：把需要管理的对象包装成 MBean， 注册到一个 MBean 服务器里，任何遵循标准的管理工具（JConsole、VisualVM、监控系统）都能查看属性、调用操作。 Tomcat 的 Server、Host、Context、连接器、线程池……全都以 MBean 的形式暴露出来。

本章目标

  • 理解 JMX 的基本概念：MBean、MBean 服务器、ObjectName、三层架构
  • 会写标准 MBean 和模型 MBean，理解两者的取舍
  • 理解 Commons Modeler 如何用 XML 描述文件省去模型 MBean 的样板代码
  • 了解 Catalina 如何为所有组件创建 MBean，以及如何用 JMX 写一个管理应用

JMX 入门

要让一个 Java 对象可以被 JMX 管理，需要为它准备一个托管 Bean（Managed Bean，MBean）。MBean 有四种：标准、动态、开放、模型。标准 MBean 最简单、最不灵活；Catalina 使用的是模型 MBean。原书时代 JMX 还需要单独下载实现（Sun 的参考实现、MX4J）；Java 5 起 JMX 已经内置在 JDK 中。

MBeanServer 与 ObjectName

MBeanServer server = MBeanServerFactory.createMBeanServer();             // 原书
MBeanServer server = ManagementFactory.getPlatformMBeanServer();         // Java 5+ 平台服务器

ObjectInstance registerMBean(Object mbean, ObjectName name);             // 注册
Set queryNames(ObjectName pattern, QueryExp query);                      // 按模式查找
Object getAttribute(ObjectName name, String attribute);
void setAttribute(ObjectName name, Attribute attribute);
Object invoke(ObjectName name, String operation, Object[] params, String[] signature);

标准 MBean

步骤：① 写一个「类名 + MBean」的接口，列出要暴露的方法；② 让类实现它；③ 创建 ObjectName，注册到 MBean 服务器。

CarMBean 接口 + Car 类
public interface CarMBean {
    public String getColor();
    public void setColor(String color);
    public void drive();
}

public class Car implements CarMBean {
    private String color = "red";
    public String getColor() { return color; }
    public void setColor(String color) { this.color = color; }
    public void drive() {
        System.out.println("Baby you can drive my car.");
    }
}

Baby you can drive my car.

getter/setter 成对出现的 getColor/setColor 被识别为可读写属性 Color，其余方法是操作。从接口中删掉 drive，管理程序就再也调用不到它——这就是「选择暴露什么」。缺点也很明显：必须修改被管理的类，让它实现接口。

模型 MBean

模型 MBean 不需要修改被管理的类。你使用 JMX 提供的 ModelMBean 实现（默认是 RequiredModelMBean），再用一个 ModelMBeanInfo 对象「描述」要暴露的属性和操作，最后用 setManagedResource(car, "ObjectReference") 告诉它管理哪个对象。

attributes[0] = new ModelMBeanAttributeInfo("Color", "java.lang.String",
    "the color.", true, true, false, null);
operations[0] = new ModelMBeanOperationInfo("drive", "the drive method",
    null, "void", MBeanOperationInfo.ACTION, null);
...
mBeanInfo = new ModelMBeanInfoSupport(MANAGED_CLASS_NAME, null, attributes, null, operations, null);

RequiredModelMBean modelMBean = new RequiredModelMBean(mBeanInfo);
modelMBean.setManagedResource(car, "ObjectReference");
mBeanServer.registerMBean(modelMBean, objectName);

Commons Modeler

手写 ModelMBeanInfo 太繁琐。Commons Modeler 让你用 XML 描述文件代替代码：

<mbeans-descriptors>
  <mbean name="myMBean"
         className="javax.management.modelmbean.RequiredModelMBean"
         description="The ModelMBean that manages our Car object"
         type="ex20.pyrmont.modelmbeantest.Car">
    <attribute name="Color" description="The car color" type="java.lang.String"/>
    <operation name="drive" description="drive method" impact="ACTION" returnType="void">
      <parameter name="driver" description="the driver parameter" type="java.lang.String"/>
    </operation>
  </mbean>
</mbeans-descriptors>
类 / 元素作用
<mbean>name 唯一名字；className 模型 MBean 的实现类（默认 BaseModelMBean）；type 被管理资源的类；domain、group
<attribute> / <operation> / <parameter>属性（可读写、getMethod/setMethod）、操作（impact：ACTION、INFO…）、参数
Registry读描述文件（loadRegistry），提供 MBeanServer，查找 ManagedBean
ManagedBean代替 MBeanInfo，createMBean() 直接生成模型 MBean
BaseModelMBeanModeler 自己的 ModelMBean 实现，resource 字段指向被管理的对象；可以继承它来覆盖或增加属性、操作

Catalina 的 MBean

Catalina 的所有组件都在 org.apache.catalina.mbeans 包的 mbeans-descriptors.xml 中声明，例如 StandardServer：

<mbean name="StandardServer"
       className="org.apache.catalina.mbeans.StandardServerMBean"
       description="Standard Server Component"
       domain="Catalina" group="Server"
       type="org.apache.catalina.core.StandardServer">
  <attribute name="port" description="TCP port for shutdown messages" type="int"/>
  <attribute name="shutdown" description="Shutdown password" type="java.lang.String"/>
  <operation name="store" description="Save current state to server.xml file"
             impact="ACTION" returnType="void"/>
</mbean>
🏷

ClassNameMBean

继承 BaseModelMBean，额外提供只读属性 className——被管理资源本身没有这个属性。

💾

StandardServerMBean

覆盖 store() 操作：把当前配置写回 server.xml。

🏭

MBeanFactory

工厂 MBean：createStandardContext(parent, path, docBase)、removeContext(name) 等，让管理程序增删组件。

🔧

MBeanUtils

静态工具：为 Server、Service、Context… 创建 MBean、生成 ObjectName、销毁 MBean。

本章应用：MyAdmin

原书写了一个特权应用 /myadmin（描述符里 privileged="true"），它的 Servlet 从 ServletContext 属性里取出 Registry 和 MBeanServer，然后：

public void init() throws ServletException {
    registry = (Registry) getServletContext().getAttribute("org.apache.catalina.Registry");
    mBeanServer = (MBeanServer) getServletContext().getAttribute("org.apache.catalina.MBeanServer");
}

private void listAllContexts(PrintWriter out) throws Exception {
    ObjectName objName = new ObjectName("Catalina:type=Context,*");      // 模式查询
    Set set = mBeanServer.queryNames(objName, null);
    for (Object obj : set) {
        out.print(obj + " <a href=?action=removeContext&contextObjectName="
                  + URLEncoder.encode(obj.toString(), "UTF-8") + ">remove</a><br/>");
    }
}

private void removeContext(String contextObjectName, PrintWriter out) throws Exception {
    ObjectName factory = new ObjectName("Catalina:type=MBeanFactory");
    mBeanServer.invoke(factory, "removeContext",
        new String[] { contextObjectName }, new String[] { "java.lang.String" });
}

③ Commons Modeler → Tomcat 内置的 modeler

和 Digester 一样，Tomcat 把 Commons Modeler 也并入了自己的代码：org.apache.tomcat.util.modeler。描述文件格式不变，Tomcat 每个包里的 mbeans-descriptors.xml 依然用它。

Registry registry = Registry.getRegistry(null);
registry.loadDescriptors("modern.ch20.modelmbeantest2", ModelAgent.class.getClassLoader());   // 读 mbeans-descriptors.xml
MBeanServer mBeanServer = registry.getMBeanServer();

ManagedBean managed = registry.findManagedBean("myMBean");
DynamicMBean mbean = managed.createMBean(car);                 // 一行生成模型 MBean
mBeanServer.registerMBean(mbean, objectName);

④ 让迷你容器也能被 JMX 管理：MXBean

Java 6 引入了 MXBean：接口名以 MXBean 结尾，只使用「开放类型」（基本类型、String、集合等），任何 JMX 客户端不需要我们的类也能显示。配合一个适配器 record，不用修改 StandardContext 本身，又比手写 ModelMBeanInfo 简单得多：

public interface ContextMXBean {
    String getPath();
    String getDocBase();
    boolean isRunning();
    int getActiveSessions();
    void start() throws Exception;
    void stop() throws Exception;
    void reload();
}

public record ContextAdmin(StandardContext context) implements ContextMXBean {
    @Override public boolean isRunning() { return context.isRunning(); }
    @Override public void stop() throws Exception { context.stop(); }
    ...
}

// MiniJmxServer：为第 18 章自动部署出的每个 Context 注册一个 MBean
mbs.registerMBean(new ContextAdmin(context),
        new ObjectName("Mini:type=Context,path=" + ObjectName.quote(context.getPath())));
mbs.invoke(app1, "stop", null, null);              // 只通过 MBeanServer 操作

⚠ JMX 等于远程控制

能连上 JMX 的人可以停止应用、修改配置，甚至通过某些 MBean 执行任意代码。用 -Dcom.sun.management.jmxremote.port=… 开放远程 JMX 时，一定要启用认证（jmxremote.password）和 TLS，或者只绑定本机、通过 SSH 隧道访问。原书要求 MyAdmin 是 privileged 应用，而现在任何代码都能调用 getPlatformMBeanServer()——这也是 Tomcat 不再推荐在同一个实例里跑不受信任应用的原因之一。

小结

  • JMX 通过 MBean 服务器把被管理对象暴露给管理程序；每个 MBean 由 ObjectName（域 + 键值对）唯一标识。
  • 标准 MBean 要求类实现「类名 + MBean」接口；模型 MBean 不修改类，用 ModelMBeanInfo 描述属性和操作。
  • Commons Modeler（现在是 Tomcat 内置的 modeler）用 XML 描述文件代替手写 ModelMBeanInfo。
  • Tomcat 4 由 ServerLifecycleListener 在 Server 启动时递归创建 MBean；Tomcat 7 起由各组件在 init 阶段自行注册。
  • 现代 Java：JMX 内置于 JDK，用平台 MBean 服务器；MXBean 是让自己的组件可管理的最简单方式；远程 JMX 必须做好安全防护。

动手练习

  1. 运行 MiniJmxServer，打开 jconsole 连接它，在 MBeans 页签里找到 Mini 域，用界面调用 /app1 的 stop 操作，然后 curl 验证返回 503。
  2. 给 Tomcat 11 版本查询线程池 MBean 的 currentThreadsBusy 和 maxThreads 属性，用一个循环每秒打印一次，再用 ab 压测观察变化。
  3. 给迷你容器的 StandardServer 也写一个 MXBean，暴露 port 和一个 shutdown() 操作——你就得到了一个比关闭端口更安全（可以加认证）的远程关闭方式。
  4. 让 ContextAdmin 在应用启动、停止时发出 JMX 通知（NotificationBroadcasterSupport），在 JConsole 中订阅它。
