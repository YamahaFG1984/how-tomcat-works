第 14 章

Server 与 Service

到目前为止，我们总是手动创建一个连接器、一个容器，把它们连起来，然后「按回车停止」。 这一章引入最后两个组件：Service 把一个容器和多个连接器组合在一起； Server 是整个 Catalina 的根，它提供了优雅的启动和关闭机制——在一个专门的端口上等待关闭命令。

本章目标

  • 理解 Server、Service、Connector、Engine 之间的组合关系
  • 弄清 initialize / start / await / stop 的调用顺序以及启停的先后
  • 理解关闭端口的工作原理和它的安全考量
  • 把这套结构对应到 Tomcat 的 server.xml

组件全家福

这个结构和 Tomcat 的 conf/server.xml 一一对应：

<Server port="8005" shutdown="SHUTDOWN">
  <Service name="Catalina">
    <Connector port="8080" protocol="HTTP/1.1" connectionTimeout="20000" />
    <Connector port="8443" protocol="HTTP/1.1" SSLEnabled="true" ... />
    <Engine name="Catalina" defaultHost="localhost">
      <Host name="localhost" appBase="webapps" autoDeploy="true">
        <Context path="/app1" docBase="app1" />
      </Host>
    </Engine>
  </Service>
</Server>

StandardServer 中和生命周期相关的四个方法是 initialize、start、stop、await，用法固定为：

public void start() throws LifecycleException {
    if (started)
        throw new LifecycleException(sm.getString("standardServer.start.started"));
    lifecycle.fireLifecycleEvent(BEFORE_START_EVENT, null);
    lifecycle.fireLifecycleEvent(START_EVENT, null);
    started = true;
    synchronized (services) {
        for (int i = 0; i < services.length; i++) {
            if (services[i] instanceof Lifecycle)
                ((Lifecycle) services[i]).start();         // 启动每个 Service
        }
    }
    lifecycle.fireLifecycleEvent(AFTER_START_EVENT, null);
}

await()：关闭端口

serverSocket = new ServerSocket(port, 1, InetAddress.getByName("127.0.0.1"));   // 只监听本机
while (true) {
    socket = serverSocket.accept();
    socket.setSoTimeout(10 * 1000);                  // 连上来不说话？10 秒后放弃
    stream = socket.getInputStream();

    StringBuffer command = new StringBuffer();
    int expected = 1024;                             // 最多读这么多：防止 DoS
    while (expected < shutdown.length()) {
        if (random == null)
            random = new Random(System.currentTimeMillis());
        expected += (random.nextInt() % 1024);
    }
    while (expected > 0) {
        int ch = stream.read();
        if (ch < 32)                                  // 控制字符或 EOF：结束
            break;
        command.append((char) ch);
        expected--;
    }
    socket.close();
    if (command.toString().equals(shutdown))
        break;                                       // 命令正确：跳出循环，await 返回
    else
        System.err.println("StandardServer.await: Invalid command '" + command + "' received");
}
serverSocket.close();
⚠ 关闭端口的安全性

任何能连上 8005 端口的人发一句 SHUTDOWN 就能关掉 Tomcat。所以它只监听 127.0.0.1。但同一台机器上的其他用户、或者通过 SSRF 漏洞让服务器自己访问 localhost，都能触发它。现代 Tomcat 的安全指南建议：把 shutdown 改成一个长随机字符串，或者干脆设置 port="-1" 关闭这个端口，改用操作系统信号（kill，见第 16 章的关闭钩子）停止 Tomcat。

Service 接口与 StandardService

Service 持有一个容器和多个连接器。有多个连接器，Tomcat 就能同时服务多种协议——一个处理 HTTP，一个处理 HTTPS，所有连接器都把请求交给同一个容器。

ⓘ 8005 还是 8085？

原书正文多处写「端口 8085」，但 Stopper 的代码和 Tomcat 默认的 server.xml 用的都是 8005。以 8005 为准。

① await()：更紧凑，也更谨慎

public void await() throws IOException {
    if (port < 0) {
        return;                                   // port = -1：不开关闭端口
    }
    try (var serverSocket = new ServerSocket(port, 1, InetAddress.getLoopbackAddress())) {
        while (true) {
            String command;
            try (Socket socket = serverSocket.accept()) {
                socket.setSoTimeout(10_000);
                command = readCommand(socket.getInputStream());     // 最多 1024 个字符，遇控制字符停止
            } catch (IOException e) {
                System.err.println("StandardServer.await: " + e);
                continue;                         // 原书在这里 System.exit(1)
            }
            if (MessageDigest.isEqual(command.getBytes(UTF_8), shutdown.getBytes(UTF_8))) {
                return;                           // 常数时间比较
            }
            System.err.println("StandardServer.await: Invalid command '" + command + "' received");
        }
    }
}

③ Tomcat 11：同样的 Server、Service、关闭端口

嵌入式 Tomcat 默认 server.getPort() 为 -1（不开关闭端口），await() 会一直阻塞到主线程被中断。同一个 Stopper 可以关闭迷你服务器，也可以关闭 Tomcat 11——它们说的是同一种「协议」。

小结

  • Server 是整个 Catalina 的根，包含若干 Service；Service 包含一个容器（Engine）和多个连接器。
  • 调用顺序：initialize → start → await → stop；启动先容器后连接器，停止先连接器后容器。
  • await() 在关闭端口（默认 8005，只监听 127.0.0.1）等待关闭命令，读取有长度和超时限制。
  • Stopper（以及 Tomcat 的 shutdown.sh）就是连上关闭端口发一句 SHUTDOWN。
  • 这套结构就是 server.xml 的骨架；生产环境应保护或关闭关闭端口。

动手练习

  1. 在 Java 17 版中把 shutdown 命令改成启动时随机生成的 UUID，并把它写进一个只有当前用户可读的文件（PosixFilePermissions），让 Stopper 从文件里读取。
  2. 在 Service 运行期间调用 service.addConnector(new HttpConnector(8082))，验证新连接器会被立即初始化并启动。
  3. 给 StandardServer 加一个关闭钩子（第 16 章）：用户按 Ctrl+C 时也能调用 stop()。
