第 12 章

StandardContext

Context 代表一个 Web 应用。除了包含若干 Wrapper，它还要协调载入器、会话管理器、域、资源等一大堆组件。 这一章拆解 StandardContext：它如何启动、如何确认自己「配置好了」、 如何按照 Servlet 规范把 URL 映射到 Wrapper、如何在重载时暂停请求， 以及 Tomcat 5 引入的共享后台线程。

本章目标

  • 理解 configured 与 available 两个标志，以及配置监听器的角色
  • 按顺序说出 StandardContext.start() 做的事
  • 掌握 Servlet URL 映射的四条规则：精确、前缀、扩展名、默认
  • 理解 Tomcat 5 的 backgroundProcess() 如何让所有组件共用一个后台线程
ⓘ 本章原书没有示例程序

原书本章只讲解 StandardContext 的源码，前几章的程序已经在用它了。Java 17 版专门为本章写了三个可运行的示例：映射规则演示 MapperDemo、组合了映射 + 重载暂停 + 共享后台线程的 Bootstrap，以及 Tomcat 11 的 EmbeddedMapping。

配置：configured 与 available

StandardContext 构造之后必须调用 start() 才能处理请求。启动可能失败，失败时 available 属性为 false。启动成功的前提是 Context 被正确配置：读取全局默认 web.xml（%CATALINA_HOME%/conf/web.xml）和应用自己的 web.xml、安装认证器阀等。

构造器里最重要的一件事是给管道设置基础阀：

public StandardContext() {
    super();
    pipeline.setBasic(new StandardContextValve());
    namingResources.setContainer(this);
}

start() 做了什么

invoke 与重载暂停

Tomcat 4 中，StandardContext 的 invoke 先检查应用是否正在重载，是的话就一直等到重载结束：

public void invoke(Request request, Response response) throws IOException, ServletException {
    while (getPaused()) {               // 正在重载：每秒检查一次
        try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
        }
    }
    if (swallowOutput) {                // 把 System.out 的输出捕获进日志
        try {
            SystemLogHandler.startCapture();
            super.invoke(request, response);
        } finally {
            String log = SystemLogHandler.stopCapture();
            if (log != null && log.length() > 0) log(log);
        }
    } else {
        super.invoke(request, response);
    }
}

Tomcat 5 去掉了这个 invoke 覆盖，检查重载的逻辑移到了 StandardContextValve.invoke 里。

映射：四条规则

StandardContextValve 首先要找到处理请求的 Wrapper。Tomcat 4 中这由 StandardContextMapper 完成：ContainerBase 的 addDefaultMapper() 通过反射创建它，map() 方法按 Servlet 规范依次尝试四条规则：

// Rule 2 -- Prefix Match
if (wrapper == null) {
    servletPath = relativeURI;
    while (true) {
        name = context.findServletMapping(servletPath + "/*");
        if (name != null)
            wrapper = (Wrapper) context.findChild(name);
        if (wrapper != null) {
            pathInfo = relativeURI.substring(servletPath.length());
            if (pathInfo.length() == 0)
                pathInfo = null;
            break;
        }
        int slash = servletPath.lastIndexOf('/');    // 去掉最后一段再试
        if (slash < 0)
            break;
        servletPath = servletPath.substring(0, slash);
    }
}

匹配成功的同时确定了 servletPath 和 pathInfo：前缀匹配时 servletPath 是匹配上的前缀，剩下的部分是 pathInfo。Tomcat 5 删除了 Mapper 接口，映射改由连接器阶段的 org.apache.tomcat.util.http.mapper.Mapper 完成，结果直接保存在请求对象中：Wrapper wrapper = request.getWrapper();

重载支持

reloadable 属性决定是否开启重载：web.xml 被修改或 WEB-INF/classes 中的类被重新编译时重新加载应用。Context 依赖载入器发现修改（第 8 章）。Tomcat 4 中，WebappLoader.setContainer() 会把 Context 的 reloadable 值同步给自己，并注册为 Context 的属性变化监听器；setReloadable() 从 false 变 true 时 threadStart()，从 true 变 false 时 threadStop()。

Tomcat 5 的 backgroundProcess

线程由 ContainerBase 的 threadStart() 创建（backgroundProcessorDelay > 0 时）。ContainerBackgroundProcessor 循环睡眠，然后调用 processChildren()：切换上下文类加载器 → 调用当前容器的 backgroundProcess() → 递归处理那些自己没有设置 delay 的子容器。

public void backgroundProcess() {
    if (!started)
        return;
    count = (count + 1) % managerChecksFrequency;
    if ((getManager() != null) && (count == 0)) {
        getManager().backgroundProcess();             // 清理过期会话
    }
    if (getLoader() != null) {
        if (reloadable && (getLoader().modified())) {
            reload();                                 // 类被修改了：重载
        }
        if (getLoader() instanceof WebappLoader) {
            ((WebappLoader) getLoader()).closeJARs(false);
        }
    }
}

① 四条规则 + record 结果

public record MappingResult(String wrapperName, Rule rule, String servletPath, String pathInfo) {
    public enum Rule { EXACT, PREFIX, EXTENSION, DEFAULT }
}

public Optional<MappingResult> map(String relativeURI) {
    String name = relativeURI.equals("/") ? null : findServletMapping.apply(relativeURI);
    if (name != null) return Optional.of(new MappingResult(name, EXACT, relativeURI, null));

    String servletPath = relativeURI;
    while (true) {                                                  // 最长前缀优先
        name = findServletMapping.apply(servletPath + "/*");
        if (name != null) {
            String pathInfo = relativeURI.substring(servletPath.length());
            return Optional.of(new MappingResult(name, PREFIX, servletPath, pathInfo.isEmpty() ? null : pathInfo));
        }
        int slash = servletPath.lastIndexOf('/');
        if (slash < 0) break;
        servletPath = servletPath.substring(0, slash);
    }
    ... // 扩展名、默认
    name = findServletMapping.apply("/");
    return Optional.ofNullable(name).map(n -> new MappingResult(n, DEFAULT, relativeURI, null));
}

② 重载期间暂停：一个 lambda 阀

public StandardContext() {
    // Tomcat 5 起，「重载中就等待」从 invoke() 移进了管道
    getPipeline().addValve((request, response, next) -> {
        while (paused) {
            Thread.sleep(100);
        }
        next.invokeNext(request, response);
    });
}

@Override
public synchronized void reload() {
    paused = true;
    try {
        super.reload();
    } finally {
        paused = false;              // 用 finally 保证即使重载失败也不会永远暂停
    }
}

③ 共享后台线程

public static ScheduledExecutorService start(Container top, int delaySeconds) {
    ScheduledExecutorService executor = Executors.newSingleThreadScheduledExecutor(...);
    executor.scheduleWithFixedDelay(() -> processChildren(top), delaySeconds, delaySeconds, TimeUnit.SECONDS);
    return executor;
}

static void processChildren(Container container) {
    Thread thread = Thread.currentThread();
    ClassLoader original = thread.getContextClassLoader();
    try {
        if (container.getLoader() != null) {
            thread.setContextClassLoader(container.getLoader().getClassLoader());
        }
        if (container instanceof BackgroundProcessable bp) {
            bp.backgroundProcess();
        }
    } finally {
        thread.setContextClassLoader(original);
    }
    for (Container child : container.findChildren()) {
        processChildren(child);
    }
}

为此，第 8 章的 WebappLoader 增加了 modified() 方法，第 9 章的 StandardManager 在 checkInterval = 0 时不再启动自己的线程——它们的周期性工作统一由 Context 的 backgroundProcess() 驱动，和 Tomcat 5 的改造如出一辙。

④ Tomcat 11：HttpServletMapping

Servlet 4.0 新增了 request.getHttpServletMapping()，应用代码可以直接知道自己是按哪条规则被匹配到的。规范还新增了第五种情况 CONTEXT_ROOT（映射模式为空字符串 ""，只匹配上下文根）：

HttpServletMapping m = request.getHttpServletMapping();
out.println("mappingMatch = " + m.getMappingMatch() + ", pattern = " + m.getPattern()
        + ", matchValue = " + m.getMatchValue());
💡 现代 Tomcat 的后台线程

Tomcat 9 起，后台处理不再是一个裸线程，而是 Server 级别的一个工具线程池（utilityThreads，线程名 Catalina-utility-N），ContainerBase 用它调度 backgroundProcess()。运行 EmbeddedMapping 时你会在 periodic 事件里看到这个线程名。

小结

  • StandardContext 启动时补齐缺少的组件（Resources → Loader → Manager），启动子组件，并在 START 事件中由 ContextConfig 完成配置。
  • configured 为真才会设置 available，否则调用 stop()。
  • URL 映射四条规则：精确 → 最长前缀 → 扩展名 → 默认；同时确定 servletPath 和 pathInfo。
  • 重载期间 paused 为真，新请求等待重载完成。
  • Tomcat 5 引入共享后台线程，backgroundProcess() 代替了载入器和管理器各自的线程；Tomcat 9 起改为工具线程池调度。

动手练习

  2. 在 Java 17 版的 backgroundProcess() 里加一项任务：每 10 次巡检打印一次当前活动会话数。
  3. 在 reload() 里加一个 Thread.sleep(3000)，重载期间用 curl 发请求，观察请求被阻塞到重载结束才返回。
