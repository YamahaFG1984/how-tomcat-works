第 1 章

一个简单的 Web 服务器

Tomcat 再复杂，最底层干的事情也只有一件：在某个端口上等浏览器连进来，读一段文本，再写回一段文本。 这一章我们用三个类、不到 150 行代码写出一个能返回 HTML 和图片的 Web 服务器， 把后面 19 章要用到的「地基」先打牢。

本章目标

  • 看懂一条 HTTP 请求和一条 HTTP 响应的文本结构
  • 理解 Socket（客户端套接字）和 ServerSocket（服务端套接字）的分工
  • 读懂原书 ex01.pyrmont 包里的 HttpServer / Request / Response
  • 知道原书代码的几个缺陷，以及在 Java 17 里怎么写得更安全、更简洁

HTTP：一问一答的文本协议

HTTP（超文本传输协议）是浏览器和 Web 服务器之间的「对话规则」。它有两个特点，初学者一定要先记住：

  • 请求—响应：永远是客户端先开口（发请求），服务器只能回答（发响应），服务器没法主动「打电话」给浏览器。
  • 跑在 TCP 之上：HTTP 报文本身就是一段文本，靠可靠的 TCP 连接传输，默认端口 80（本书的例子都用 8080）。

原书写作时（2004 年）最新的是 HTTP/1.1（RFC 2616）。今天 HTTP/1.1 的规范已经更新为 RFC 9110/9112，还有了 HTTP/2、HTTP/3，但报文的语义完全没变，Tomcat 11 依然默认讲 HTTP/1.1。

HTTP 请求的三个部分

一条 HTTP 请求由三部分组成：请求行、请求头、实体正文（body）。请求头和正文之间隔着一个空行。

HTTP/1.1 定义了 GET、POST、HEAD、OPTIONS、PUT、DELETE、TRACE 等方法，最常用的是 GET（取资源）和 POST（提交数据）。 URI 通常以 / 开头，表示相对于服务器根目录的路径。

HTTP 响应的三个部分

响应的结构和请求几乎一模一样，只是第一行换成了状态行：协议版本、状态码、原因短语。

HTTP/1.1 200 OK
Server: Microsoft-IIS/4.0
Date: Mon, 5 Jan 2004 13:13:33 GMT
Content-Type: text/html
Last-Modified: Mon, 5 Jan 2004 13:13:12 GMT
Content-Length: 112

<html>
<head><title>HTTP Response Example</title></head>
<body>Welcome to Brainy Software</body>
</html>
状态码含义例子
2xx成功200 OK
3xx重定向，去别处找302 Found、304 Not Modified
4xx客户端的错404 Not Found、401 Unauthorized
5xx服务器的错500 Internal Server Error
💡 自己动手看报文

用 curl -v http://example.com/ 就能看到真实的请求和响应文本。以 > 开头的是发出的请求，以 < 开头的是收到的响应头。

Socket 与 ServerSocket

套接字（socket）是网络连接的一个端点。两台机器上的程序各拿一个 socket，就能通过它互相收发字节流。 Java 用两个类来表示它们，分工很明确：

📞

Socket

主动去连别人。new Socket("127.0.0.1", 8080)，然后用输入流读、输出流写。

📡

ServerSocket

守在端口上等别人来连。accept() 会一直阻塞，直到有连接进来，返回一个 Socket。

🔗

绑定地址

服务器监听哪个 IP。127.0.0.1 表示只接受本机连接。

🚶

backlog

排队等待 accept 的连接最多几个，超过就拒绝。原书设成 1。

⚠ println 发的不是 CRLF

println 在 Linux/macOS 上只输出 \n，而 HTTP 要求 \r\n。大多数服务器会宽容处理，但写协议代码时最好显式写 \r\n。另外原书片段里 new Socket("127.0.0.1", "8080") 的端口写成了字符串，是个笔误，编译不过。

本章应用：三个类的 Web 服务器

原书的应用在 ex01.pyrmont 包里，只有三个类，它只能返回 webroot 目录下的静态文件（HTML、图片），并把收到的请求原文打印到控制台。

HttpServer：主循环

WEB_ROOT 指向「执行 java 命令时所在目录」下的 webroot。await 方法（不叫 wait，是因为 wait 已经是 Object 上的线程方法）创建 ServerSocket 后进入循环：

public static final String WEB_ROOT =
    System.getProperty("user.dir") + File.separator + "webroot";
private static final String SHUTDOWN_COMMAND = "/SHUTDOWN";
private boolean shutdown = false;

public void await() {
    ServerSocket serverSocket = null;
    int port = 8080;
    try {
        serverSocket = new ServerSocket(port, 1, InetAddress.getByName("127.0.0.1"));
    } catch (IOException e) {
        e.printStackTrace();
        System.exit(1);
    }
    while (!shutdown) {
        Socket socket = null;
        InputStream input = null;
        OutputStream output = null;
        try {
            socket = serverSocket.accept();
            input = socket.getInputStream();
            output = socket.getOutputStream();
            Request request = new Request(input);
            request.parse();
            Response response = new Response(output);
            response.setRequest(request);
            response.sendStaticResource();
            socket.close();
            shutdown = request.getUri().equals(SHUTDOWN_COMMAND);
        } catch (Exception e) {
            e.printStackTrace();
            continue;
        }
    }
}

Request：只取 URI

parse() 从输入流里一次读最多 2048 字节，拼成字符串打印出来，再交给 parseUri。parseUri 的思路很朴素：请求行是「方法 空格 URI 空格 版本」，那么第一个空格和第二个空格之间就是 URI。

public void parse() {
    StringBuffer request = new StringBuffer(2048);
    int i;
    byte[] buffer = new byte[2048];
    try {
        i = input.read(buffer);        // 只读一次！
    } catch (IOException e) {
        e.printStackTrace();
        i = -1;
    }
    for (int j = 0; j < i; j++) {
        request.append((char) buffer[j]);
    }
    System.out.print(request.toString());
    uri = parseUri(request.toString());
}

private String parseUri(String requestString) {
    int index1 = requestString.indexOf(' ');
    if (index1 != -1) {
        int index2 = requestString.indexOf(' ', index1 + 1);
        if (index2 > index1)
            return requestString.substring(index1 + 1, index2);
    }
    return null;
}

Response：把文件原样写回去

public void sendStaticResource() throws IOException {
    byte[] bytes = new byte[BUFFER_SIZE];
    FileInputStream fis = null;
    try {
        File file = new File(HttpServer.WEB_ROOT, request.getUri());
        if (file.exists()) {
            fis = new FileInputStream(file);
            int ch = fis.read(bytes, 0, BUFFER_SIZE);
            while (ch != -1) {
                output.write(bytes, 0, ch);
                ch = fis.read(bytes, 0, BUFFER_SIZE);
            }
        } else {
            String errorMessage = "HTTP/1.1 404 File Not Found\r\n" +
                "Content-Type: text/html\r\n" +
                "Content-Length: 23\r\n" +
                "\r\n" +
                "<h1>File Not Found</h1>";
            output.write(errorMessage.getBytes());
        }
    } catch (Exception e) {
        System.out.println(e.toString());
    } finally {
        if (fis != null) fis.close();
    }
}
🔑 一个值得注意的细节

找到文件时，原书没有写状态行和响应头，直接把文件字节丢给浏览器。这不是合法的 HTTP 响应，只是浏览器足够宽容（把它当成远古的 HTTP/0.9 响应）才能显示。用 curl 请求时，新版本 curl 会直接报错「Received HTTP/0.9 when not allowed」。

原书代码的局限

作为教学代码它足够简单，但请你记住下面这些问题——后面几章会逐个解决它们，这也是理解 Tomcat 为什么要设计得那么复杂的线索：

问题后果谁来解决
input.read(buffer) 只读一次、最多 2048 字节请求被 TCP 拆成多段到达时会读不全第 3 章 SocketInputStream
只解析了 URI拿不到请求头、参数、Cookie第 3 章 HttpRequest
单线程，一次只服务一个连接一个慢客户端会卡住所有人第 4 章处理器池
成功时不写状态行和响应头不是合法 HTTP 响应第 3 章 HttpResponse
new File(WEB_ROOT, uri) 不检查 ..路径穿越漏洞：/../../etc/passwd 可以读走任意文件本章 Java 17 版
请求 / 时 file.exists() 为真（是目录）FileInputStream 打开目录抛异常，浏览器收不到任何响应本章 Java 17 版

try-with-resources 取代手写 finally

原书
Socket socket = null;
try {
    socket = serverSocket.accept();
    ...
    socket.close();     // 抛异常时不会执行
} catch (Exception e) {
    e.printStackTrace();
    continue;
}
Java 17
try (Socket socket = serverSocket.accept()) {
    Request request = Request.parse(socket.getInputStream());
    if (request == null) continue;
    new Response(socket.getOutputStream())
        .sendStaticResource(request);
    shutdown = SHUTDOWN_COMMAND.equals(request.uri());
} catch (IOException e) {
    e.printStackTrace();
}   // 不管有没有异常，socket 都会被关闭

record 取代可变的 Request

原书的 Request 要先 new、再 parse()、再 getUri()，中间任何一步忘了调用就会拿到 null。用 record 加静态工厂方法，解析完就是一个字段齐全的不可变对象：

public record Request(String method, String uri, String protocol) {

    public static Request parse(InputStream input) throws IOException {
        var reader = new BufferedReader(
            new InputStreamReader(input, StandardCharsets.ISO_8859_1));
        String requestLine = reader.readLine();   // 一直读到 \r\n，不怕被拆包
        if (requestLine == null || requestLine.isBlank()) {
            return null;
        }
        System.out.println(requestLine);
        for (String line; (line = reader.readLine()) != null && !line.isEmpty(); ) {
            System.out.println(line);              // 请求头读到空行为止
        }
        String[] parts = requestLine.split(" ");
        return parts.length == 3
                ? new Request(parts[0], parts[1], parts[2])
                : new Request(parts[0], parts.length > 1 ? parts[1] : "/", "HTTP/1.0");
    }
}

NIO Files + 完整响应头 + 防路径穿越

public void sendStaticResource(Request request) throws IOException {
    Path file = resolve(request.uri());
    if (file != null && Files.isRegularFile(file)) {          // 目录不算
        byte[] body = Files.readAllBytes(file);
        String type = Files.probeContentType(file);           // text/html、image/gif……
        writeHead(200, "OK", type != null ? type : "application/octet-stream", body.length);
        output.write(body);
    } else {
        byte[] body = "<h1>File Not Found</h1>".getBytes(StandardCharsets.UTF_8);
        writeHead(404, "Not Found", "text/html; charset=UTF-8", body.length);
        output.write(body);
    }
    output.flush();
}

static Path resolve(String uri) {
    String path = uri.split("\\?", 2)[0];                       // 去掉 ?a=b
    Path file = HttpServer.WEB_ROOT.resolve(path.substring(1)).normalize();
    return file.startsWith(HttpServer.WEB_ROOT) ? file : null;  // 跳出 webroot 就拒绝
}

然后在浏览器里打开 http://localhost:8080/index.html。用 curl 可以把三种情况都试一遍：

$ curl -i http://localhost:8080/index.html
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 156
Connection: close

$ curl -s -o /dev/null -w '%{http_code}\n' --path-as-is http://localhost:8080/../pom.xml
404

$ curl http://localhost:8080/SHUTDOWN       # 服务器打印「收到 /SHUTDOWN，服务器退出」

浏览器加载 index.html 时，控制台会先后打印两条请求：一条 GET /index.html，一条 GET /images/logo.gif——HTML 里的 <img> 让浏览器又发了一次请求。

小结

  • HTTP 报文 = 起始行 + 头部 + 空行 + 正文；请求的起始行是「方法 URI 版本」，响应的是「版本 状态码 原因」。
  • ServerSocket.accept() 阻塞等待连接，返回的 Socket 负责收发数据。
  • 原书的服务器：单线程循环 → 解析 URI → 把 webroot 下的文件写回去 → 关闭连接；访问 /SHUTDOWN 停机。
  • 它不读请求头、不写响应头、不支持并发，也有路径穿越漏洞；这些不足正是后续章节的出发点。

动手练习

  3. 让请求 / 时自动返回 /index.html。
  4. 思考：如果某个客户端连上后迟迟不发数据，服务器会怎样？试着用 telnet 连上不说话，再用浏览器访问。（答案在第 4 章。）
