第 7 章

日志记录器

日志记录器（Logger）是 Catalina 中最简单的组件：它挂在容器上，负责把消息记录下来。 Tomcat 4 提供了三种实现——写到标准输出、写到标准错误、写到按天滚动的文件。 这一章很短，但它展示了一个经典的设计：抽象基类实现所有重载，子类只实现一个方法。

本章目标

  • 理解 Logger 接口和「详细级别（verbosity）」的含义
  • 理解 LoggerBase 如何让子类只关心「写到哪里」
  • 读懂 FileLogger 按日期滚动日志文件的实现
  • 知道现代 Tomcat 为什么换成了 JULI，以及 JULI 的 FileHandler 如何继承了 FileLogger 的设计

Logger 接口

public interface Logger {
    public static final int FATAL = Integer.MIN_VALUE;
    public static final int ERROR = 1;
    public static final int WARNING = 2;
    public static final int INFORMATION = 3;
    public static final int DEBUG = 4;

    public Container getContainer();
    public void setContainer(Container container);
    public String getInfo();
    public int getVerbosity();
    public void setVerbosity(int verbosity);
    public void addPropertyChangeListener(PropertyChangeListener listener);
    public void log(String message);
    public void log(Exception exception, String msg);
    public void log(String message, Throwable throwable);
    public void log(String message, int verbosity);
    public void log(String message, Throwable throwable, int verbosity);
    public void removePropertyChangeListener(PropertyChangeListener listener);
}

带 verbosity 参数的两个 log 方法会先比较级别：传入的级别不高于（数值不大于）记录器设定的级别时才真正记录。

Tomcat 4 的三种 Logger

LoggerBase

LoggerBase 是抽象类，默认级别 ERROR。它实现了所有带额外参数的 log 重载——它们最终都调用唯一的抽象方法 log(String msg)。这样每个子类只需要决定「写到哪里」：

protected int verbosity = ERROR;

public abstract void log(String msg);       // 子类唯一要实现的方法

public void log(String message, int verbosity) {
    if (this.verbosity >= verbosity)
        log(message);
}

public void setVerbosityLevel(String verbosity) {
    if ("FATAL".equalsIgnoreCase(verbosity))
        this.verbosity = FATAL;
    else if ("ERROR".equalsIgnoreCase(verbosity))
        this.verbosity = ERROR;
    ...
}

public class SystemOutLogger extends LoggerBase {
    public void log(String msg) {
        System.out.println(msg);
    }
}

public class SystemErrLogger extends LoggerBase {
    public void log(String msg) {
        System.err.println(msg);
    }
}

FileLogger：按天滚动

FileLogger 把消息写进文件，文件名由前缀 + 日期 + 后缀组成，比如 FileLog_2004-01-05.txt。每写一条日志都检查日期，日期变了就关闭旧文件、打开新文件。它还实现了 Lifecycle，stop 时关闭文件。

public void log(String msg) {
    Timestamp ts = new Timestamp(System.currentTimeMillis());
    String tsString = ts.toString().substring(0, 19);   // "yyyy-mm-dd hh:mm:ss"
    String tsDate = tsString.substring(0, 10);          // "yyyy-mm-dd"

    if (!date.equals(tsDate)) {
        synchronized (this) {
            if (!date.equals(tsDate)) {
                close();
                date = tsDate;
                open();
            }
        }
    }
    if (writer != null) {
        if (timestamp) writer.println(tsString + " " + msg);
        else           writer.println(msg);
    }
}

private void open() {
    File dir = new File(directory);
    if (!dir.isAbsolute())
        dir = new File(System.getProperty("catalina.base"), directory);
    dir.mkdirs();
    try {
        String pathname = dir.getAbsolutePath() + File.separator + prefix + date + suffix;
        writer = new PrintWriter(new FileWriter(pathname, true), true);   // 追加模式
    } catch (IOException e) {
        writer = null;
    }
}

private void close() {
    if (writer == null) return;
    writer.flush();
    writer.close();
    writer = null;
    date = "";
}
⚠ 双重检查的隐患

date 不是 volatile，第一次检查在锁外读它，第二次在锁内。一个线程正在换文件时，另一个线程可能在锁外看到新 date 却拿到了已被关闭（null）的 writer，于是这条日志被悄悄丢掉。日志丢几条通常无伤大雅，但这个模式照搬到别处就可能出大问题。Java 17 版把「检查 + 写入」整体放进了 synchronized。

本章应用

应用和第 6 章几乎一样，只改了两个类：SimpleContext 增加了 logger 字段并在启动/停止时记日志；Bootstrap 创建一个 FileLogger 交给 Context。连接器也会通过 container.getLogger() 把自己的消息写到这个 Logger 里。

Java 17：LocalDateTime
@Override
public synchronized void log(String message) {
    LocalDateTime now = LocalDateTime.now();
    if (!now.toLocalDate().equals(date)) {
        close();
        date = now.toLocalDate();
        open();
    }
    writer.println(timestamp
        ? TIMESTAMP.format(now) + " " + message
        : message);
}

private void open() {
    try {
        Path file = currentFile();                      // catalina.base/logs/FileLog_2026-10-28.txt
        Files.createDirectories(file.getParent());
        writer = new PrintWriter(Files.newBufferedWriter(file, StandardCharsets.UTF_8,
                StandardOpenOption.CREATE, StandardOpenOption.APPEND), true);
    } catch (IOException e) {
        throw new UncheckedIOException(e);              // 原书吞掉异常，导致日志静默丢失
    }
}

Java 17 版的 SimpleContext 继承第 6 章的版本，只增加了 Logger 的启停和 log() 方法；启动类还用一个 lambda 阀把每个请求记进同一个日志文件——这就是 Tomcat AccessLogValve 的雏形。

③ 现代 Tomcat：JULI

Tomcat 5.5 删掉了 org.apache.catalina.Logger 这一整套，改用 JULI（Java Util Logging Implementation）：一个基于 JDK 自带 java.util.logging 的实现，能为每个 Web 应用单独配置日志。组件里通过 org.apache.juli.logging.Log 取日志对象，配置写在 conf/logging.properties。

小结

  • Logger 挂在容器上；带级别的 log 只在级别足够时才记录。
  • LoggerBase 实现所有重载，子类只实现 log(String)：SystemOut、SystemErr、File 三种。
  • FileLogger 用「前缀 + 日期 + 后缀」命名文件，日期变化时自动换文件，stop 时关闭文件。
  • 现代 Tomcat 用基于 java.util.logging 的 JULI，FileHandler 延续了 FileLogger 的设计并增加了过期清理和异步写入。

动手练习

  1. 给 Java 17 版的 FileLogger 加一个 maxDays 属性：每次换文件时删除 N 天前的日志文件（提示：Files.list + 解析文件名中的日期）。
  2. 为了测试跨天滚动，把 LocalDateTime.now() 换成 LocalDateTime.now(clock)，注入一个可控的 java.time.Clock，写一个测试验证换天后产生了新文件。
  3. 把 FileLogger 改成异步：log() 只把消息放进 BlockingQueue，由一个后台线程负责写文件。想一想 stop() 时要注意什么。
